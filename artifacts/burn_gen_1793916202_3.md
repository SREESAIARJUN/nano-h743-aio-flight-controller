# 3-Axis Gimbal: FOC Motor Control, Anti-Cogging Feedforward, and Dual ICM-42688-P Sensor Fusion

## 0. Assumptions and System Architecture

| Item | Assumed value |
|---|---|
| Motors | Gimbal BLDC (GBM2804-class), 12N14P → pole pairs `p = 7`, R ≈ 5.6 Ω, L ≈ 2.2 mH, Kt ≈ 0.075 N·m/A |
| Commutation sensor | 14-bit absolute magnetic encoder (AS5048A / MT6701) on each motor shaft |
| MCU | STM32G4/H7-class with FPU, 3× center-aligned PWM, inline/low-side current sensing |
| IMUs | 2× ICM-42688-P on the camera plate, SPI at 24 MHz, ODR 8 kHz |
| Bus | 12–16 V |

### Loop Rates

```
                 ┌─────────── 1 kHz ─────────┐ ┌────── 4 kHz ──────┐ ┌──── 20 kHz ────┐
θ_ref ─►(Σ)─► Angle P + ω_ff ─► (Σ)─► Velocity PI ─► (Σ)─► iq* ─► Current PI (d,q) ─► SVPWM ─► Motor
         ▲  (IMU attitude, axis-projected)  ▲  (gyro rate, axis-projected) ▲ +i_cog(θm)  ▲ Clarke/Park
         └──────────── Mahony AHRS ◄── dual-IMU fusion + filters (8 kHz)   └── encoder θm (commutation)
```

The key architectural choices are:

1. **Inertial velocity feedback.** The velocity loop is closed on the fused gyro rate projected onto each motor axis, not on the encoder derivative. The encoder is used for commutation, cogging lookup, and joint-angle limits.
2. **Rate separation.** Each loop is roughly 4–5× slower in bandwidth than the loop inside it:
   - Current loop: ~1.5 kHz
   - Velocity loop: ~80 Hz
   - Angle loop: ~15 Hz
