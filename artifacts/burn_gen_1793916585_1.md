# STM32H743 Nano FC + 4-in-1 80 A ESC: Systems Architecture & Mathematical Model

## 0. Assumptions and Architecture Corrections

I don't have a datasheet set or prior spec for "Job #17," so every number below comes from stated assumptions. Swap in your actual MOSFET, driver and stackup values. The equations are written so you can do that.

**Two architectural points need correcting before design starts:**

1. **The H743 does not commutate the motors.** ArduPilot sends DShot to ESC firmware (AM32 or BLHeli_32) running on a separate MCU per channel. The architecture is therefore H743 FC → 4× ESC MCU (e.g., AT32F421K8U7 or STM32G071) → gate drivers → 24 MOSFETs. Driving gates directly from the H743 is not supported by ArduPilot.
2. **80 A on a "nano" board is a burst rating only.** Section 3 shows that on a 20×20 mm board, all four channels at 80 A reach thermal limits in roughly 1 second. Treat 80 A as a per-channel, ≤1 s, single-digit-duty-cycle rating, not a continuous one.

## 1. Conduction Loss Model

AM32 uses 6-step trapezoidal commutation with synchronous rectification. At any instant, two phases carry the full phase current I:
- The PWM'd leg alternates between high-side (on-time D) and low-side (off-time 1−D).
- The opposite leg's low-side is fully on.

So exactly two FETs conduct I at all times, apart from dead time.

**Temperature-adjusted on-resistance:**

$$R_{ds,hot} = R_{ds(on),25}\cdot k_T = 1.2\,\text{m}\Omega \times 1.6 = 1.92\,\text{m}\Omega$$

**Per-channel conduction loss.** In 6-step operation the phase current is quasi-DC, so I_rms ≈ I:

$$P_{cond} = 2\,I^2 R_{ds,hot} = 2(80)^2(1.92\times10^{-3}) = 24.6\,\text{W}$$

**Copper loss:**

$$P_{cu} = I^2 R_{cu} = 6400 \times 0.5\times10^{-3} = 3.2\,\text{W}$$

**Per-FET averaging.** Each FET conducts about one third of the electrical cycle, so

$$\bar P_{FET,cond} \approx \tfrac{24.6}{6} \approx 4.1\,\text{W}$$

The *instantaneous* loss while a FET is conducting is

$$I^2R_{ds,hot} = 12.3\,\text{W}$$

Use 12.3 W for junction transient analysis.

**R_ds(on) feedback loop.** R_ds(on) rises with temperature, which raises loss, which raises temperature. Solve this iteratively:

$$T_j^{(n+1)} = T_a + R_{th,ja}\cdot I^2 R_{25}\left[1+\alpha\,(T_j^{(n)}-25)\right]$$

with α ≈ 0.006 K⁻¹. If $R_{th,ja}\cdot I^2 R_{25}\cdot\alpha \ge 1$, the loop has no stable point (thermal runaway). This is the formal reason steady-state 80 A is impossible on this footprint.

## 2. Switching Loss Model at 48 kHz

Only the PWM'd leg hard-switches.

**(a) V–I overlap (hard switching):**

$$P_{sw} = \tfrac12 V_{bus} I (t_r+t_f) f_{sw} = 0.5(25.2)(80)(30\,\text{ns})(48\,\text{k}) = 1.45\,\text{W}$$

**(b) Dead-time body-diode conduction:**

$$P_{dt} = V_f\,I\,(2t_{dt})\,f_{sw} = 0.8(80)(200\,\text{ns})(48\,\text{k}) = 0.61\,\text{W}$$

**(c) Reverse recovery:**

$$P_{rr} = Q_{rr}V_{bus}f_{sw} = 50\,\text{nC}(25.2)(48\,\text{k}) = 0.06\,\text{W}$$

**(d) C_oss discharge:**

$$P_{oss} = \tfrac12 C_{oss}V_{bus}^2 f_{sw} = 0.5(1.5\,\text{nF})(635)(48\,\text{k}) = 0.023\,\text{W}$$

**(e) Gate drive.** This loss lands in the driver and gate resistors, not the FET:

$$P_g = Q_g V_{gs} f_{sw}\times 2_{\text{(active pair)}} = 60\,\text{nC}(10)(48\,\text{k})(2) = 0.058\,\text{W}$$

**Per-channel total at 80 A:**

| Loss term | Power |
|---|---|
| Conduction | 24.6 W |
| Copper | 3.2 W |
| Switching (V–I overlap) | 1.45 W |
| Dead-time diode | 0.61 W |
| Reverse recovery + C_oss + gate | 0.14 W |
| **Total per channel** | **≈ 30.0 W** |
| **4 channels simultaneous** | **≈ 120 W** |

**Design insight.** At 48 kHz, switching losses are only about 7% of the total; conduction dominates. Raising f_sw (smoother motor, less audible noise) costs little. Lowering R_ds(on) is the only lever that matters at 80 A.

**Dead-time sensitivity.** Every 50 ns of dead time adds about 0.15 W per channel. Tune AM32 dead time to the minimum the FD6288-class driver plus your gate resistors allow without shoot-through, and verify it on a scope.

**PWM resolution check (AM32 on a 64 MHz timer):**

$$N = \frac{64\,\text{MHz}}{48\,\text{kHz}} \approx 1333 \text{ counts} \approx 10.4\text{-bit}$$

This is adequate. Note that dead time consumes about 6 counts per edge at 100 ns.
