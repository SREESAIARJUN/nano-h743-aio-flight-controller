# STM32H743 Nano FC + 4-in-1 ESC (Job #32): Architecture, Loss Model, DShot DMA, Netlist

## 0. Architecture Corrections

Two problems in the brief would cause a failed design, so I've corrected them before deriving anything.

**1. The STM32H743 should not drive the power stage directly.**
- Four 6-step or FOC motors need 24 gate signals, and each motor needs its own commutation timebase.
- The H743 has only two advanced timers (TIM1 and TIM8, 6 complementary outputs each) plus the HRTIM (10 outputs). That totals 22 outputs on shared timebases, so it is short on both count and independence.
- Bidirectional DShot also only makes sense when an FC talks to separate ESC MCUs.

**Architecture used here:**
- The H743 acts as the flight controller running ArduPilot.
- Four AT32F421K8U7 (or STM32G071) MCUs run AM32, one per motor.
- Each ESC MCU drives an FD6288-class 3-phase gate driver, which drives 6× N-MOSFETs.

**2. "80 A burst" on a nano (20×20 or 30×30 mm) board is a time-limited rating, not a continuous one.**
- Section 3 derives the allowable burst duration.
- On a 30×30 board with all four motors at 80 A, that duration is about **2–3 s**.
- If marketing needs "80 A burst", the datasheet must state a duration (for example "80 A / 2 s, single channel").
