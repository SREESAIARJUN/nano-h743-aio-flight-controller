# FOC Motor Control and Dual-IMU Sensor Fusion: 3-Axis Gimbal (Job #60)

I don't have the Job #60 specification, so this design states its assumptions (§0). Every gain, harmonic order, and filter frequency is parameterised, so you can substitute your real motor, encoder, and airframe data without changing the structure.

---

## 0. Assumptions and Timing Architecture

| Item | Assumed value |
|---|---|
| MCU | STM32G4/H7-class Cortex-M with FPU (single-precision float) |
| Motor | Gimbal BLDC, 12N14P (p = 7 pole pairs), R ≈ 5–15 Ω, L ≈ 1–3 mH |
| Encoder | 14-bit absolute magnetic (AS5048A / MT6701 class), one per axis |
| Current sense | 2 or 3 inline/low-side shunts (voltage-mode fallback in §1.6) |
| IMUs | 2× ICM-42688-P on the camera plate, SPI, 8 kHz ODR, ±2000 dps / ±16 g |
| Mount | Multirotor, so dominant vibration is at the propeller rotation frequency and its harmonics (≈ 80–400 Hz) |

**Rate hierarchy.** Each outer loop has 5–10× lower bandwidth than the loop inside it.

```
PWM 40 kHz  ─► Current loop (FOC)     20 kHz   BW ≈ 1.5–2 kHz
IMU 8 kHz   ─► IMU filter + fusion     8 kHz
               Velocity loop           4 kHz   BW ≈ 150–250 Hz
               Attitude estimator      1 kHz
               Angle (stabilisation)   1 kHz   BW ≈ 20–40 Hz
```

## 1. Field-Oriented Control (Inner Current Loop)

### 1.1 Electrical Angle

$$\theta_e = p\,(\theta_m - \theta_{\text{off}}) \bmod 2\pi$$

θ_off is found at commissioning by applying v_d > 0, v_q = 0 and recording θ_m once the rotor settles.

### 1.2 Clarke and Park Transforms (Amplitude-Invariant)

$$i_\alpha = i_a,\qquad i_\beta = \tfrac{1}{\sqrt3}(i_a + 2i_b)\quad(\text{with } i_a+i_b+i_c=0)$$

$$\begin{bmatrix} i_d\\ i_q\end{bmatrix}=\begin{bmatrix}\cos\theta_e & \sin\theta_e\\ -\sin\theta_e & \cos\theta_e\end{bmatrix}\begin{bmatrix}i_\alpha\\ i_\beta\end{bmatrix}$$

### 1.3 PMSM Model in the dq Frame

$$v_d = R i_d + L\dot i_d - \omega_e L i_q,\qquad v_q = R i_q + L\dot i_q + \omega_e L i_d + \omega_e
