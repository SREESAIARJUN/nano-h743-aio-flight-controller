# Job #22: 3-Axis Gimbal FOC Control Loop and Dual-IMU Sensor Fusion

**Design baseline.** I don't have the Job #22 spec sheet, so this design uses the assumptions below. Every parameter is a `constexpr` or config field, so you can substitute your real values.

| Item | Assumption |
|---|---|
| MCU | STM32G474 (170 MHz, FPU, CORDIC), one per gimbal or one for all 3 axes |
| Motors | 3× gimbal BLDC, 12N14P (pole pairs p = 7), R ≈ 5–15 Ω, L ≈ 1–3 mH |
| Rotor sensor | 14-bit absolute magnetic encoder (AS5048A / MT6701) per axis |
| Current sense | 2-shunt low-side, synchronous to PWM center |
| IMUs | 2× ICM-42688-P on the camera plate, SPI @ 24 MHz, ODR = 8 kHz |
| Rates | Current loop 20 kHz · IMU filtering 8 kHz · velocity loop and AHRS 4 kHz · attitude loop 1 kHz |
| Kinematic order | Yaw (base) → Roll → Pitch (camera) |

---

## 1. System Architecture

```
          1 kHz                    4 kHz                        20 kHz
 q_ref ─►[Attitude P/PI]─ω_ref─►[Velocity PI]─i_q*─(+)─►[Current PI d/q]─►[SVPWM]─► Motor
          ▲      (camera frame→joint J⁻¹)  ▲           ▲  ▲                 ▲
          │                                │   i_ff,cog┘  │ i_d*=0          │ θ_e
     q̂ (AHRS) ◄── fused ω, a ◄── Dual-IMU vibration    Cogging FF ◄── θ_m (encoder)
                                rejection (8 kHz)       (harmonic LMS)
                                ▲
                        IMU A ──┴── IMU B
```

**Bandwidth separation rule.** Each outer loop gets at least 5× less bandwidth than the loop inside it:

- Current loop: ω_c ≈ 2π·2000 rad/s
- Velocity loop: ω_v ≈ 2π·150 rad/s
