# 3-Axis Gimbal: FOC Control, Anti-Cogging Feedforward, and Dual-IMU Vibration Rejection

I have no specification for "Job #32", so the design below rests on stated assumptions. Every motor- and frame-specific number lives in one config struct. Replace the assumptions with your measured values before tuning.

---

## 0. Assumptions and Loop Architecture

| Item | Assumed value |
|---|---|
| MCU | Cortex-M4F/M7 with single-precision FPU (e.g. STM32G474 / H723) |
| Motor | Gimbal BLDC, 12N14P (pole pairs p = 7), R = 5.6 Ω, L = 2.1 mH, Kt ≈ 0.08 N·m/A |
| Encoder | 14-bit absolute magnetic (AS5048A/MT6701), read every PWM cycle |
| Inverter | 3-phase, V_dc = 12–16 V, 3 low-side shunts |
| IMUs | 2 × ICM-42688-P over SPI at 24 MHz, ODR 8 kHz, ±2000 dps, ±16 g. **IMU-C** on the camera plate (payload), **IMU-B** on the base/handle |
| Loop rates | Current/FOC 20 kHz → Velocity 4 kHz → Angle 1 kHz → Attitude estimator 4 kHz |
| Bandwidths | Current ≈ 1.5 kHz, velocity ≈ 60–120 Hz, angle ≈ 10–20 Hz (≥ 5× separation at each stage) |

```
             ┌─────────────── 1 kHz ──────────────┐ ┌───── 4 kHz ─────┐ ┌──── 20 kHz ────┐
θ_ref ──►(Σ)─► P(+ff) ─► ω_ref ─►(Σ)─► PI+AW ─► τ* ─(+τ_cog_ff +τ_base_ff)─► iq* ─► FOC PI ─► SVPWM
          ▲                       ▲                                              ▲
     θ_cam (fused attitude)   ω_cam (filtered IMU-C gyro, on motor axis)    i_abc, θ_e (encoder)
```

The inertial loops (angle and velocity) close on the **camera IMU**. The current loop and cogging compensation use the **motor encoder**. The base IMU supplies disturbance feedforward and a redundancy check.
