# 3-Axis Gimbal: FOC Control Loop and Dual-IMU Sensor Fusion Design

I don't have the specification for "Job #15", so this design rests on the explicit assumptions below. Every parameter is a named constant, so you can substitute your real values.

| Item | Assumed value |
|---|---|
| Motors | 3× BLDC gimbal motors, 12N14P (p = 7 pole pairs), R ≈ 10 Ω, L ≈ 3 mH |
| Rotor sensing | 14-bit absolute magnetic encoder per axis (e.g. AS5048/MT6701) |
| MCU | Cortex-M4F/M7 class (single-precision FPU) |
| Current loop | 20 kHz |
| IMU acquisition / velocity loop | 8 kHz |
| Angle loop / attitude estimator | 1 kHz |
| IMUs | 2× ICM-42688-P on the camera plate, mirrored about the plate centroid (r₂ = −r₁), gyro ODR 8 kHz, ±2000 dps |
| Gimbal order | Base → Yaw → Roll → Pitch → Camera |

## 1. System Architecture

```
              1 kHz                 8 kHz                    20 kHz
 q_ref ─►[Attitude err]─►ω_ref─►[Rate PI + FF]─►τ_ref─►[÷Kt + cogging FF]─►iq_ref─►[Current PI dq]─►SVPWM
              ▲                 ▲ (gyro, camera frame→joint axes)        ▲ id,iq ◄─ Clarke/Park ◄─ ia,ib
              │                 │                                        │ θe ◄─ encoder
   Mahony AHRS (1 kHz) ◄── Dual ICM-42688-P fusion ◄── AAF ► LPF ► static notch ► adaptive notch (8 kHz)
```

Key design choice: for stabilisation, the velocity loop is closed on **inertial gyro rate** projected onto each motor axis, not on encoder rate. The encoder is used only for commutation (θₑ), cogging-map indexing, the joint Jacobian, and soft limits.

## 2. FOC Current Loop (20 kHz)

### 2.1 Transforms

Assuming a balanced three-phase system (iₐ + i_b + i_c = 0):

**Clarke transform**

$$i_\alpha = i_a,\qquad i_\beta = \frac{i_a + 2 i_b}{\sqrt3}$$

**Park transform**, with electrical angle θₑ = p(θ_m − θ_off):

$$\begin{bmatrix}i_d\\ i_q\end{bmatrix}=\begin{bmatrix}\cos\theta_e & \sin\theta_e\\ -\sin\theta_e & \cos\theta_e\end{bmatrix}\begin{bmatrix}i_\alpha\\ i_\beta\end{bmatrix}$$

### 2.2 Motor model (surface PM, L_d = L_q = L)

$$v_d = R i_d + L\dot i_d - \omega_e L i_q,\qquad v_q = R i_q + L\dot i_q + \omega_e L i_d + \omega_e\lambda$$

$$\tau = K_t\, i_q,\qquad K_t = \tfrac32\, p\, \lambda$$

### 2.3 Current PI design (pole-zero cancellation)

The plant per axis after decoupling is G(s) = 1/(Ls + R). Choosing

$$C(s) = K_p + \frac{K_i}{s},\qquad K_p = L\,\omega_c,\quad K_i = R\,\omega_c$$

cancels the electrical pole at −R/L. The closed loop then becomes a first-order system ω_c/(s + ω_c).

- Pick ω_c ≈ 2π·1.5 kHz, which is about f_s/13. This leaves margin for the 1.5-sample PWM and computation delay.
- The phase lost to that delay at crossover is ω_c · 1.5 T_s ≈ 0.7 rad ≈ 40°, giving a phase margin of about 50°.

**Decoupling feedforward**

$$v_d^{ff} = -\omega_e L i_q,\qquad v_q^{ff} = \omega_e (L i_d + \lambda)$$

**Voltage saturation**

Clamp the voltage vector to the linear SVPWM limit:

$$\|v_{dq}\| \le V_{dc}/\sqrt3$$

Apply the clamp with q-axis priority.

### 2.4 Discrete PI with back-calculation anti-windup

$$u_k^{*} = K_p e_k + I_k,\qquad u_k = \mathrm{sat}(u_k^{*})$$

$$I_{k+1} = I_k + K_i T_s e_k + K_{aw} T_s (u_k - u_k^{*})$$

The anti-windup gain K_aw is typically set to K_i/K_p
