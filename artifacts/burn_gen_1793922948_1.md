# 3-Axis Gimbal FOC Control and Dual-IMU Sensor Fusion Design (Job #46)

## 0. Design Assumptions

I don't have the Job #46 spec sheet. The baseline below is typical for a camera gimbal. Every parameter is in a `constexpr` config block, so you can substitute your real values without restructuring anything.

| Item | Assumed value |
|---|---|
| Motors | 3× gimbal BLDC, 12N14P (pole pairs p = 7), R ≈ 5 Ω, L ≈ 2 mH, λ ≈ 0.012 V·s |
| Encoders | 14-bit absolute magnetic (MT6701/AS5048A class), one per axis |
| MCU | STM32G4 / H7 class with FPU, 3 timer-synchronized PWM banks |
| Kinematic order | Base → **Yaw (z)** → **Roll (x)** → **Pitch (y)** → Camera |
| IMU-A | ICM-42688-P on the camera plate (attitude and inertial rate feedback) |
| IMU-B | ICM-42688-P on the base/handle (disturbance feedforward) |
| Loop rates | Current/FOC 20 kHz · IMU, velocity and attitude 4 kHz · cogging learning 1 kHz |

### Loop Hierarchy

```
 attitude ref ─► [Attitude P + ω_ff] ─► ω_cam* ─► J⁻¹(θ)·(ω_cam* − ω_base) ─► q̇*
   ▲ IMU-A quaternion (Mahony)                     ▲ IMU-B feedforward
                                                      │
 q̇* ─► [Velocity PI, back-calc AW] ─► i_q* + i_q,cog(θ) + i_q,ff ─► [FOC current PI] ─► SVPWM
          ▲ inertial joint rate q̇ = J⁻¹(ω_A − R·ω_B)   (filtered, notched)
```

**Bandwidth separation rule.** Keep at least 5× between loop bandwidths:
- current loop ≈ 2 kHz
- velocity loop ≈ 300 Hz
- attitude loop ≈ 30–60 Hz
