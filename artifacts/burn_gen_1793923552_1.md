# 3-Axis Gimbal: FOC Control, Anti-Cogging Feedforward, and Dual-IMU Vibration Rejection

## 0. Assumptions

I don't have the Job #22 specification, so this design uses the typical brushless gimbal configuration below. Every hardware-dependent value is a named constant in the code, so you can substitute your own.

| Item | Assumed value |
|---|---|
| Motors | 3× gimbal BLDC (e.g. GBM2804-class), 12N14P, p = 7 pole pairs, R ≈ 10 Ω, L ≈ 2 mH (phase-equivalent) |
| Position sensor | 14-bit absolute magnetic encoder per joint (AS5048A / MT6701) |
| MCU | STM32G4 / H7 class, FPU, 3× complementary PWM, synchronous ADC |
| Current sense | Low-side or inline shunt, 2 phases sampled at PWM center |
| IMUs | 2× ICM-42688-P on the camera plate, SPI @ 24 MHz, ODR 8 kHz |
| Kinematic chain | Base → Yaw (z) → Roll (x) → Pitch (y) → Camera |

### Loop-rate hierarchy

The bandwidth of each loop is roughly 1/5 to 1/10 of the loop inside it.

| Loop | Rate | Closed-loop bandwidth |
|---|---|---|
| Current (FOC) | 20 kHz | ω_c ≈ 2π·1500 rad/s |
| Velocity (inertial rate) | 4 kHz | ω_v ≈ 2π·120 rad/s |
| Angle (attitude) | 1 kHz | ω_θ ≈ 2π·20 rad/s |
| IMU sampling / filtering | 8 kHz → decimated to 4 kHz | — |

### Key architectural decision

The **velocity loop uses inertial rate from the camera IMUs**, projected onto each joint axis through the gimbal Jacobian. It does not use encoder differentiation. The encoder is used for commutation (θ_e), for cogging compensation, and as a fallback.

This choice is what makes the gimbal *stabilize* against base motion rather than merely hold joint angles.
