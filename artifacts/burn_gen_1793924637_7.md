# 3-Axis Gimbal FOC Control and Dual-IMU Sensor Fusion: Design Specification and Implementation

I don't have the Job #8 parameter sheet, so this design uses the assumptions below. Every value is a single `constexpr` or config field, so you can substitute yours.

| Item | Assumed value |
|---|---|
| Motors | 3× gimbal BLDC, 12N14P (pole pairs p = 7), R = 5.6 Ω, L = 2.1 mH (phase), K_t ≈ 0.11 N·m/A |
| Position sensor | 14-bit absolute magnetic encoder (AS5048A / MT6701 class) per axis |
| MCU | STM32G474 class (Cortex-M4F, 170 MHz, FPU, CORDIC) |
| Power stage | 3-phase driver with in-line or low-side current sensing, V_bus = 12–16 V |
| IMUs | 2× ICM-42688-P on the camera plate, SPI @ 24 MHz, 8 kHz ODR |
| Loop rates | Current/FOC 20 kHz · IMU 8 kHz · rate (velocity) 4 kHz · attitude (angle) 1 kHz |

## 1. Control Architecture

```
            1 kHz                 4 kHz                       20 kHz
 θ_ref ─►(Σ)─► Angle P(I) ─ω_ref─►(Σ)─► Rate PI(D) ─i_q*─►(Σ)─► FOC current PI ─► SVPWM ─► Motor
          ▲                        ▲                ▲       ▲
          │ θ_cam (IMU attitude)   │ ω_axis (gyro)  │       └ i_q,ff  (anti-cogging, enc. angle θ_m)
          │                        │                └ i_q,ff,acc (optional J·α_ref)
   Dual ICM-42688-P ─► AAF ─► dynamic notch ─► LPF ─► inverse-variance fusion ─► Mahony AHRS
```

Each signal comes from the source that suits its job:

- **Commutation and cogging compensation** use the motor encoder angle θ_m. Cogging is a function of rotor-to-stator position.
- **The rate loop** uses the gyro rate projected onto the motor axis. This gives inertial stabilization: the base can move, but the camera should not.
- **The angle loop** uses the fused IMU attitude, mapped to joint coordinates.
