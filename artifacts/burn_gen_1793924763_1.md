# 3-Axis Gimbal: FOC Motor Control and Dual-IMU Sensor Fusion Design

I don't have the Job #12 specification sheet, so the design below rests on explicit assumptions (§0). Every constant that depends on your hardware is a named parameter. Substitute your values and the equations and tuning rules still hold.

---

## 0. Assumptions and Architecture

| Item | Assumed value | Notes |
|---|---|---|
| Motors | Gimbal BLDC, 12N14P (pole pairs p = 7), R = 5.6 Ω, L = 2.1 mH, K_t ≈ 0.09 N·m/A | e.g. GBM4108 class |
| Encoder | 14-bit absolute magnetic (AS5048A / MT6701), SPI | read at FOC rate |
| Current sense | 2-phase low-side shunts, synchronous ADC | voltage-mode fallback in §1.6 |
| MCU | Cortex-M4F/M7 (STM32G4/H7), FPU | |
| IMU-A | ICM-42688-P on camera plate | attitude feedback |
| IMU-B | ICM-42688-P on base/handle | disturbance reference + feedforward |
| Gimbal order | Yaw (outer) → Roll → Pitch (inner, camera) | |

**Loop rates (all integer-divided from the PWM interrupt):**

| Loop | Rate | Ts | Target bandwidth |
|---|---|---|---|
| PWM / current (FOC) | 20 kHz | 50 µs | ω_c ≈ 2π·1500 rad/s |
| Velocity | 4 kHz | 250 µs | ω_v ≈ 2π·120 rad/s |
| IMU sampling + filters | 8 kHz ODR, FIFO-drained at 4 kHz | | |
| Attitude/angle | 1 kHz | 1 ms | ω_θ ≈ 2π·20 rad/s |
| Mahony AHRS | 1 kHz | | |

Bandwidths are separated by at least 5× between nested loops so each outer loop sees the inner loop as roughly unity gain.
