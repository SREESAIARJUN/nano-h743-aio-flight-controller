# Gimbal FOC Control and Dual-IMU Sensor Fusion: Design Specification and C++ Implementation

> **Assumptions.** I don't have the specification for Job #47, so this design uses these baseline parameters:
> - **Motor:** 3× gimbal BLDC motors, 12N14P (7 pole pairs), high-resistance windings.
> - **Encoder:** 14-bit magnetic (MT6701/AS5048-class) on each motor.
> - **MCU:** STM32G4-class with FPU.
> - **IMUs:** 2× ICM-42688-P on the camera payload.
>

## 1. Loop Architecture and Timing

| Loop | Rate | Bandwidth target | Input | Output |
|---|---|---|---|---|
| Current (d/q PI + decoupling) | 20 kHz (= PWM) | ω_c ≈ 2π·1.5 kHz | i_a, i_b, θ_e | v_α, v_β → SVPWM |
| Velocity (PI + anti-cogging FF) | 4 kHz | ω_v ≈ 2π·150 Hz | ω (gyro-fused) | i_q* |
| Angle / attitude (P + vel. FF) | 1 kHz | ω_θ ≈ 2π·30 Hz | attitude error | ω* |
| IMU acquisition + filtering | 8 kHz ODR, 4 kHz decimated | — | 2× ICM-42688-P | ω̂, q̂ |

**Bandwidth separation rule:** ω_c ≥ 5–10·ω_v and ω_v ≥ 4–5·ω_θ. This lets each inner loop be treated as unity gain (plus a first-order lag) when tuning the outer loop.

**Velocity feedback source:** the velocity loop should use the gyro (payload inertial rate), not the encoder derivative. This rejects base motion directly. The encoder is used for commutation (θ_e) and for cogging compensation (θ_m).

## 2. FOC Current Loop

### 2.1 Transforms (amplitude-invariant, balanced phases i_a + i_b + i_c = 0)

**Clarke:**

  i_α = i_a,  i_β = (i_a + 2 i_b)/√3

**Park** (θ_e = p·θ_m − θ_offset):

  i_d = i_α cos θ_e + i_β sin θ_e
  i_q = −i_α sin θ_e + i_β cos θ_e

**Inverse Park:**

  v_α = v_d cos θ_e − v_q sin θ_e
  v_β = v_d sin θ_e + v_q cos θ_e
