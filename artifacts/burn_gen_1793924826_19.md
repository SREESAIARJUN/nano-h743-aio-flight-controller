**Architecture note.** In a 4-in-1 stack, the H743 does not switch the FETs. Each ESC channel has its own MCU, typically an AT32F421 or EFM8 running AM32, BLHeli_32, or Bluejay. Those MCUs own the 48 kHz PWM and must run bidirectional-DShot-capable firmware. The H743 owns only the DShot600 command/telemetry link. Section 3 covers that link.

**Red flag (critical).** 4 × 80 A = **320 A** of battery current on a nano board, typically 20×20 or 25.5×25.5 mm. As shown below, this is only survivable as a **transient burst of a few seconds**. It is not a continuous rating. Battery pads, XT60 leads, and bus copper are as limiting as the FETs.

## 1. Conduction Loss Model

### 1.1 Topology
The model assumes 6-step trapezoidal commutation with synchronous rectification, which is AM32's default complementary PWM. At any instant, two phase legs carry current I:
- The PWM'd high side with its complementary low side, sharing time D : (1−D).
- One fully-on low side.

So at any instant, two FET channels (or one plus a complementary pair) are in series with the motor.

### 1.2 Temperature-dependent R_DS(on)
$$R_{DS}(T_j) = R_{25}\,[1+\alpha(T_j-25)]$$

### 1.3 Per-channel conduction loss
$$P_{cond,ch} = I^2\left[2R_{DS}(T_j) + 2R_{cu}\right]$$

This expression is approximately independent of D under synchronous rectification. The PWM leg always has exactly one FET conducting, apart from dead time.

Evaluated at T_j = 125 °C (R_DS = 1.45 mΩ):
$$P_{cond,ch} = 6400\,(2.9\text{ m}\Omega + 1.0\text{ m}\Omega) = 18.6 + 6.4 = \mathbf{25.0\ W}$$

The split is 18.6 W in the FETs and 6.4 W in the copper.

### 1.4 Per-FET loss
Each FET conducts during ⅓ of the electrical period.

| Loss measure | Calculation | Value |
|---|---|---|
| Instantaneous, during conduction window | I²·R_DS | 9.3 W |
| Average | 9.3 / 3 | 3.1 W |

The instantaneous value matters at low eRPM, when the commutation period is comparable to the junction time constant (τ_j ≈ 1–5 ms). At high eRPM, use the average.

### 1.5 Electro-thermal fixed point
R_DS depends on T_j, and T_j depends on loss, so iterate:
$$T_j^{(n+1)} = T_{board} + P_{FET}\big(R_{DS}(T_j^{(n)})\big)\cdot R_{jc}$$

The loop converges if
$$\frac{\partial P}{\partial T}R_{th} = I^2R_{25}\,\alpha\,R_{th} < 1.$$

Here: 6400 × 1e-3 × 0.0045 × 1.5 = 0.043, so the loop is stable. The real runaway path is board-level, analyzed in Section 4.

## 2. Switching Loss Model (48 kHz)

Only the PWM'd leg switches, so the losses below are per channel, with V = 25.2 V and I = 80 A.

| Term | Equation | Value |
|---|---|---|
| V-I overlap | ½·V·I·(t_r + t_f)·f_sw | ½·25.2·80·40 ns·48 k = **1.94 W** |
| Dead-time body diode | V_f·I·2t_dt·f_sw | 0.8·80·200 ns·48 k = **0.61 W** |
| Reverse recovery | Q_rr·V·f_sw | 50 nC·25.2·48 k = **0.06 W** |
| C_oss (2 FETs/leg) | 2·½C_oss,er·V²·f_sw | **0.05 W** |
| Gate drive (mostly in driver/R_g) | 2·Q_g·V_GS·f_sw | 2·50 nC·10·48 k = **0.05 W** |
| **Total P_sw,ch** | | **≈ 2.7 W** |

Key relationships:
- At D → 100% (true full throttle), the overlap and dead-time terms vanish. Peak switching loss occurs at partial throttle under heavy load, for example during a punch-out ramp.
- Switching loss scales linearly with f_sw. At 24 kHz, P_sw ≈ 1.35 W.
- 48 kHz is chosen for motor current ripple and acoustic reasons, not efficiency.
- Dead-time loss is about 23% of switching loss. Tightening t_dt to 50 ns saves about 0.3 W per channel, if driver propagation matching allows it.

### Total burst loss

| Item | Per channel | 4 channels |
|---|---|---|
| FET conduction (125 °C) | 18.6 W | 74.4 W |
| Copper (phase) | 6.4 W | 25.6 W |

## 3. ArduPilot Bidirectional DShot600 on the H743

### 3.1 Protocol timing

| Item | Value |
|---|---|
| Bit rate | 600 kbit/s → T_bit = 1.667 µs |
| T1H / T0H (≈75% / 37.5%) | 1.25 µs / 0.625 µs |
| Frame | 16 bits (11 throttle + 1 telemetry + 4 CRC) = 26.7 µs |
| Bidir CRC | inverted, and the line idles low (inverted signalling) |
| ESC reply | ≈30 µs after the frame. 21-bit GCR (20-bit GCR plus a start bit) at 5/4 × 600 = **750 kbit/s**, which is ≈28 µs |
| Total transaction | ≈ 26.7 + 30 + 28 + guard ≈ **90–100 µs** |

At ArduPilot's typical loop rate of 400 Hz–1 kHz, this leaves wide margin.
