# STM32H743 Nano FC + 4-in-1 ESC: 80 A Burst Thermal, 48 kHz Switching, and Bidirectional DShot600 Design

Two findings change the design brief, so they come first.

**1. The H743 does not drive the MOSFETs.** In every ArduPilot-compatible 4-in-1 stack, the STM32H743 is the flight controller. It sends DShot600 to four ESC MCUs (for example AT32F421 or STM32G071 running AM32 or BLHeli_32). Those ESC MCUs generate the 48 kHz complementary PWM. The architecture below follows that split. A single-MCU FOC design on the H743 is possible but cannot run stock ArduPilot motor output.

**2. "80 A burst" on a nano (20×20 mm) board is thermally adiabatic.** The math in Section 2 shows the board cannot reject heat at that power. Burst duration is set purely by thermal mass, at roughly 2 seconds. The figure is defensible only as a per-channel, ≤2 s, single-motor rating, not all four motors at once. That limit should appear on the spec sheet.

**Assumed component parameters.** All component values below are assumptions; replace them with your actual BOM datasheet values.

| Parameter | Assumed value |
|---|---|

## 1. Loss Model (per motor channel, 6-step trapezoidal, synchronous PWM)

At any instant, one high-side and one low-side path carry phase current I_ph. The two FETs in the switching leg share that current according to duty cycle, so the total conduction loss stays approximately 2·I²·R.

### 1.1 Conduction loss

P_cond = 2 · I_ph² · R_ds(on) · k_T

With I_ph = 80 A:

P_cond = 2 · 6400 · 1.0 mΩ · 1.5 = **19.2 W**

Add copper path loss: P_Cu = I² · R_trace. With about 0.3 mΩ of 2 oz pour plus vias in the path, that is **≈1.9 W**.

### 1.2 Switching loss (hard-switched leg, f_sw = 48 kHz)

| Term | Formula | Value |
|---|---|---|
| V-I overlap | ½ · V · I · (t_r + t_f) · f_sw = ½·25.2·80·20 ns·48 k | 0.97 W |
| Dead-time diode | V_f · I · 2t_d · f_sw = 0.8·80·400 ns·48 k | 1.23 W |
| C_oss | 2 · ½ · C_oss · V² · f_sw | 0.05 W |
| Gate drive | 2 · Q_g · V_gs · f_sw | 0.05 W (lands in driver/LDO) |
| Q_rr (estimate) | Q_rr · V · f_sw, with Q_rr ≈ 40 nC | 0.05 W |
| **P_sw total** | | **≈2.35 W** |

**Design lever:** dead-time loss exceeds overlap loss. Cutting t_dead to 100 ns, as far as gate-driver propagation-delay matching allows, saves about 0.6 W per channel.

### 1.3 Totals at the 80 A burst

| Scope | Calculation | Loss |
|---|---|---|
| Per channel | 19.2 + 1.9 + 2.35 | **≈23.5 W** |
| Per hottest FET | Conduction dominates | ≈11 W |
| All four channels | 4 × 23.5 | **≈94 W** |

Efficiency check: the output is 25.2 V · 80 A · D. At full throttle (≈2 kW per channel), losses are about 1.2%, which is fine electrically. The problem is purely thermal.

### 1.4 Frequency sensitivity

P_sw scales linearly with frequency at about 0.049 W/kHz per channel.

| f_sw | P_sw |
|---|---|
| 24 kHz | 1.2 W |
| 48 kHz | 2.35 W |
| 96 kHz | 4.7 W |

At 48 kHz, conduction loss is about 85% of the total, so switching frequency is not the thermal limiter.

## 2. Thermal Model

### 2.1 Lumped RC network

```
P_FET ──[Zth_jc]──┬──[R_board→air]── T_amb
                  │
               C_board
```

| Parameter | Value |
|---|---|
| Zth_jc, 3×3 DFN | R_th,jc ≈ 1.5 K/W; Z_th(1 s) ≈ 1.0 K/W |
| C_board (20×20 mm, 8-layer, 2 oz, FETs + caps; ≈3 g Cu-weighted) | ≈4 J/K |
| h, prop-wash convection | ≈100 W/m²K |
| A, both faces | 8×10⁻⁴ m² |
| R_board→air = 1/(hA) | ≈12.5 K/W |
| τ = R·C | ≈50 s |

### 2.2 Steady state is impossible

ΔT_ss = 94 W × 12.5 K/W ≈ 1175 K.

Because the 2–3 s burst is much shorter than the 50 s time constant, the burst is adiabatic.

### 2.3 Burst budget

Board heating rate:

dT_board/dt = P_total / C = 94 / 4 ≈ **23.5 K/s** (all four motors at 80 A)

Junction temperature:

T_j(t) = T_board,0 + (P_total/C)·t + P_FET · Z_th,jc(t)

**Constraint:** T_j ≤ 125 °C (keep 25 K margin under the 150 °C absolute maximum).

Starting at T_board,0 = 60 °C (typical hover soak):

60 + 23.5·t + 11·1.0 ≤ 125  →  **t_max ≈ 2.3 s (all four motors)**

| Load case | Heating rate | t_max |
|---|---|---|
| Single motor at 80 A, others at 20 A | ≈8 K/s | ≈6 s |
| All four at 80 A | 23.5 K/s | ≈2.3 s |

### 2.4 Recovery

At 25% cruise load (≈6 W total), the board cools along exp(−t/50 s). Recovering 40 K takes on the order of 60 s. Set the ArduPilot ESC-telemetry temperature failsafe accordingly.

### 2.5 Recommendations

- Rate the product as **"80 A burst (2 s), 45 A continuous with airflow"**.
- Run ESC firmware temperature foldback at 110 °C, derating linearly to 50% current at 125 °C.
