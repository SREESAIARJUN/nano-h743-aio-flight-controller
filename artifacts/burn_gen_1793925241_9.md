# FOC Control, Anti-Cogging, and Dual-IMU Fusion for a 3-Axis Gimbal (Job #34)

I don't have the Job #34 spec sheet, so I assumed the most common architecture below. Every assumption is a named constant in the code, so you can change one line if your hardware differs.

---

## 0. Assumptions and Timing Architecture

| Item | Assumed value |
|---|---|
| MCU | STM32G4 / H7 class: FPU, 170+ MHz, center-aligned PWM, synchronous ADC |
| Motors | 3× gimbal BLDC, 12N14P (pole pairs p = 7). Example: GBM2804 class, R ≈ 5–12 Ω, L ≈ 1–3 mH |
| Encoders | 14-bit absolute magnetic (AS5048A / MT6701) on each joint |
| Current sense | 2- or 3-shunt, sampled at the PWM center |
| IMUs | 2× ICM-42688-P on the camera plate, SPI, gyro and accel ODR 8 kHz, ±2000 dps / ±16 g |
| Kinematics | Yaw (base) → Roll → Pitch (camera) |

| Loop | Rate | Ts | Target bandwidth |
|---|---|---|---|
| Current (d/q) | 20 kHz | 50 µs | ~1.5–2 kHz |
| IMU fusion + filters | 8 kHz | 125 µs | — |
| Inertial rate (velocity) | 4 kHz | 250 µs | ~80–150 Hz |
| Attitude (angle) | 1 kHz | 1 ms | ~10–20 Hz |

Rule of thumb: each outer loop should have at most 1/5 to 1/10 the bandwidth of the loop inside it.
