# 3-Axis Gimbal FOC Control and Dual-IMU Fusion Design (Job #48)

I don't have the Job #48 spec sheet, so this design uses the **typical hardware assumptions below**. Every one is a named constant in the code, so you can substitute real values.

| Item | Assumed value |
|---|---|
| Motors | 3× gimbal BLDC, 12N14P (pole pairs p = 7), R ≈ 5–10 Ω, L ≈ 2–4 mH |
| Encoder | 14-bit absolute magnetic (AS5048A / MT6701), one per axis |
| MCU | STM32G4 / H7 class with FPU, center-aligned PWM at 20 kHz |
| Loop rates | Current: 20 kHz. Velocity: 4 kHz. Angle/attitude: 1 kHz. |
| IMUs | 2× ICM-42688-P on the camera payload, SPI, 8 kHz ODR, FIFO + shared CLKIN |
| Disturbances | Propeller/airframe vibration at 80–400 Hz plus harmonics, and motor cogging |

## Part 1 — Field-Oriented Control (Innermost Loop, 20 kHz)

### 1.1 Electrical angle

$$\theta_e = p\,(\theta_m - \theta_{\text{off}}) \bmod 2\pi$$

- θ_off is found at startup by applying v_d > 0 with θ_e = 0. The rotor aligns, and you record θ_m.
- The angle is latency-compensated for the encoder-to-PWM delay T_d, which is about 1.5·T_pwm:

$$\hat\theta_e = \theta_e + \omega_e T_d$$

### 1.2 Clarke and Park transforms

Clarke, assuming balanced phases (i_a + i_b + i_c = 0):

$$i_\alpha = i_a,\qquad i_\beta = \frac{i_a + 2 i_b}{\sqrt3}$$

Park:

$$\begin{bmatrix} i_d\\ i_q\end{bmatrix} = \begin{bmatrix}\cos\theta_e & \sin\theta_e\\ -\sin\theta_e & \cos\theta_e\end{bmatrix}\begin{bmatrix} i_\alpha\\ i_\beta\end{bmatrix}$$

### 1.3 Motor model in the dq frame

$$v_d = R i_d + L\dot i_d - \omega_e L i_q$$
