# 3-Axis Gimbal: FOC Motor Control and Dual-IMU Sensor Fusion Design

I don't have the Job #12 specification, so I've made the assumptions below explicit. Every number in this design is parameterized. Swap in your actual motor and board values and the equations and code still hold.

## 0. Assumptions and Timing Architecture

| Item | Assumed value |
|---|---|
| MCU | STM32G4 / H7 class, FPU, ≥170 MHz |
| Motor | Gimbal BLDC, 12N14P (pole pairs p = 7), R ≈ 5–15 Ω, L ≈ 2–5 mH |
| Encoder | 14-bit absolute magnetic (AS5048A / MT6701), one per axis |
| IMUs | 2× ICM-42688-P on the camera plate, SPI, gyro/accel ODR = 8 kHz |
| Inverter | 3-phase, center-aligned PWM 20–40 kHz, low-side shunts |

| Loop | Rate | Target bandwidth |
|---|---|---|
| Current (FOC) | 20 kHz | ω_c ≈ 2π·1.5 kHz |
| Encoder PLL + velocity | 10 kHz | ω_v ≈ 2π·150 Hz |
| Angle (joint) | 2 kHz | ω_θ ≈ 2π·30 Hz |
| IMU fusion + stabilization | 1–2 kHz (decimated from 8 kHz) | ~10–20 Hz attitude |

The bandwidths are separated by roughly 5–10× between loops so each inner loop looks like unity gain to the loop outside it.

## 1. Field-Oriented Current Control

### 1.1 Transforms
Use the amplitude-invariant Clarke transform with i_a + i_b + i_c = 0:

$$i_\alpha = i_a,\qquad i_\beta = \tfrac{1}{\sqrt3}(i_a + 2 i_b)$$

The Park transform, with electrical angle θ_e = p·θ_m − θ_offset, is:

$$\begin{bmatrix}i_d\\ i_q\end{bmatrix}=\begin{bmatrix}\cos\theta_e & \sin\theta_e\\ -\sin\theta_e & \cos\theta_e\end{bmatrix}\begin{bmatrix}i_\alpha\\ i_\beta\end{bmatrix}$$

The inverse Park transform is the transpose of this matrix.

### 1.2 PMSM model in the dq frame

$$v_d = R i_d + L_d \dot i_d - \omega_e L_q i_q$$
$$v_q = R i_q + L_q \dot i_q + \omega_e L_d i_d + \omega_e \lambda_m$$

The torque is τ = (3/2) p λ_m i_q = K_t i_q (assuming a surface PM, L_d ≈ L_q).

### 1.3 Current PI with decoupling, tuned by pole-zero cancellation
Each axis has the plant G(s) = 1/(Ls + R). Choose:

$$K_p = L\,\omega_c,\qquad K_i = R\,\omega_c \;\;\Rightarrow\;\; \frac{i}{i^*}= \frac{\omega_c}{s+\omega_c}$$

Add feedforward decoupling and back-EMF compensation:

$$v_d^* = PI_d(e_d) - \hat\omega_e \hat L i_q,\qquad v_q^* = PI_q(e_q) + \hat\omega_e(\hat L i_d + \hat\lambda_m)$$

### 1.4 Voltage limiting, anti-windup, and discretization
The available voltage magnitude is limited by the SVPWM linear region:

$$|v_{dq}| \le V_{max} = \frac{V_{bus}}{\sqrt3}\cdot m_{max},\quad m_{max}\approx0.95$$

Priority goes to v_d. Then:

$$v_q \le \sqrt{V_{max}^2 - v_d^2}$$

Each PI is discretized with backward Euler and uses back-calculation anti-windup:

$$u_k = K_p e_k + I_k,\quad \bar u_k = \text{sat}(u_k),\quad I_{k+1} = I_k + T_s\big[K_i e_k + K_{aw}(\bar u_k - u_k)\big],\quad K_{aw}\approx K_i/K_p$$

The computation and PWM-update delay is about 1.5·T_s. Keep ω_c·1.5·T_s < 0.2 rad to retain at least 60° of phase margin. At 20 kHz this gives ω_c ≲ 2π·2 kHz.

### 1.5 SVPWM by min-max zero-sequence injection

$$v_{a,b,c} = \text{invClarke}(v_\alpha,v_\beta),\quad v_0 = -\tfrac12(\max + \min),\quad d_x = \tfrac12 + \frac{v_x+v_0}{V_{bus}}$$

## 2. Encoder Velocity Estimation (PLL / Tracking Observer)

Differentiating a 14-bit encoder directly is very noisy: Δθ = 3.8e-4 rad per count at 10 kHz corresponds to 3.8 rad/s per LSB. Use a type-2 tracking loop instead:

$$e = \text{wrap}(\theta_{meas} - \hat\theta),\quad \hat\omega \mathrel{+}= T_s K_i e,\quad \hat\theta \mathrel{+}= T_s(\hat\omega + K_p e)$$

with K_p = 2ζω_n and K_i = ω_n². Choose ω_n ≈ 2π·400–800 Hz and ζ = 1, so the observer is several times faster than the velocity loop. Optionally add the torque feedforward T_s·K_t·i_q/J to the ω̂ update. This reduces observer lag during acceleration.
