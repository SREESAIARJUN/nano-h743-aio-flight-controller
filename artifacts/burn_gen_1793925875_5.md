# 3-Axis Gimbal FOC and Sensor Fusion: Control Design and C++ Implementation

I don't have the Job #38 spec sheet, so this design uses the assumptions in §0. Every derived gain is a closed-form function of those parameters. If you substitute your real values, the equations still hold.

---

## 0. Assumptions and System Architecture

| Item | Assumed value | Symbol |
|---|---|---|
| Motor | Gimbal PMSM, 12N14P (12 slots, 14 poles) | N_s = 12, p = 7 pole pairs |
| Phase resistance / inductance | 5.0 Ω / 2.0 mH (line-to-neutral) | R, L |
| Flux linkage | 0.012 V·s/rad | λ |
| Torque constant | K_t = 1.5·p·λ = 0.126 N·m/A | K_t |
| Rotor + load inertia (pitch) | 4×10⁻⁴ kg·m² | J |
| Viscous friction | 1×10⁻⁴ N·m·s/rad | B |
| Encoder | 14-bit magnetic (MT6701 / AS5048A) | θ_m |
| MCU | STM32G474 / H7 with FPU (and CORDIC if available) | |
| Bus voltage | 12 V | V_dc |
| IMUs | 2 × ICM-42688-P. IMU-C on the camera plate, IMU-B on the base/handle | |

**Loop rates (all phase-locked to the PWM timer):**

| Loop | Rate | Ts | Closed-loop bandwidth |
|---|---|---|---|
| Current (FOC) | 20 kHz | 50 µs | ω_c = 2π·1500 rad/s |
| IMU sample + filters | 8 kHz | 125 µs | (ODR) |
| Velocity | 4 kHz (÷5) | 250 µs | ω_v = 2π·60 rad/s |
| Angle + attitude fusion | 1 kHz (÷20) | 1 ms | ω_θ = 2π·12 rad/s |
