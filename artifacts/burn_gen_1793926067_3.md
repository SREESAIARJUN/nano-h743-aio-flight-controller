# 3-Axis Gimbal: FOC Control Loop and Dual-IMU Fusion Design

I don't have the Job #27 specification, so this design uses common gimbal hardware. Each assumption is marked as a constant in the code. Change them to match your hardware.

| Item | Assumption |
|---|---|
| Motors | 3× hollow-shaft gimbal BLDC (GBM2804-class): 12N14P, p = 7 pole pairs, R ≈ 5.6 Ω, L ≈ 2.2 mH, K_t ≈ 0.08 N·m/A |
| Encoder | 14-bit absolute magnetic (AS5048A / MT6701) per axis, read over SPI at 20 kHz |
| Current sense | 2-shunt or 3-shunt low-side, sampled at the PWM center |
| MCU | Cortex-M4F/M7 with single-precision FPU (STM32G4 / H7) |
| IMUs | 2× ICM-42688-P on the camera plate, separate SPI chip-selects, 8 kHz ODR |
| Loop rates | Current 20 kHz, velocity 4 kHz, attitude/angle 1 kHz |

## 1. Loop Architecture

```
            ┌──────────────── 1 kHz ────────────────┐ ┌──── 4 kHz ────┐ ┌──────── 20 kHz ────────┐
 q_ref ──►  Attitude error ─► Angle P + rate FF ─► ω* ─► Velocity PI ─►(+)─► i_q* ─► Current PI (d,q)
 (camera)   (quaternion)      (per joint)              ▲               ▲ i_q,cog     │  + decoupling
     ▲                                                 │               │             ▼
     │                                     ω_joint (gyro-projected)    │         Inv. Park ─► SVPWM ─► Bridge
  Dual-IMU fusion ◄── notch/LPF ◄── 2× ICM-42688-P                Anti-cogging        ▲
  (Mahony quaternion)                                             LUT / LMS (θ_m)     │
                                                                       ▲        Clarke/Park ◄─ i_a,i_b
                                                                  Encoder θ_m ──► θ_e = p·θ_m − θ_0
```

Two design decisions shape this structure:

- **Velocity feedback.** The velocity loop uses the inertial rate of the camera, projected onto each joint axis and taken from the fused gyros. It does not use the differentiated encoder. Stabilization only cares about inertial motion. The gyro is also a much cleaner, lower-latency rate source than a differentiated encoder. The encoder is used for commutation and for indexing the cogging table. An encoder PLL provides a fallback velocity.
- **Bandwidth separation.** Each loop is 5–10× slower than the loop inside it:

  ω_c,i ≈ 2π·1500 rad/s  ≫  ω_c,ω ≈ 2π·150  ≫  ω_c,θ ≈ 2π·20

## 2. FOC Current Loop (20 kHz)

### 2.1 Transforms

**Clarke transform** (amplitude-invariant, assuming i_a + i_b + i_c = 0):

  i_α = i_a,  i_β = (i_a + 2·i_b)/√3

**Park transform**, with electrical angle θ_e = p·θ_m − θ_0 (θ_0 found during alignment):

  i_d = i_α·cos θ_e + i_β·sin θ_e
  i_q = −i_α·sin θ_e + i_β·cos θ_e

**Inverse Park transform:**

  v_α = v_d·cos θ_e − v_q·sin θ_e
  v_β = v_d·sin θ_e + v_q·cos θ_e

### 2.2 Plant and PI gain design

The PMSM model in the dq frame is:

  v_d = R·i_d + L·di_d/dt − ω_e·L·i_q
  v_q = R·i_q + L·di_q/dt + ω_e·(L·i_d + λ_m)

Add the decoupling feedforward terms:

  v_d,ff = −ω_e·L·i_q
  v_q,ff = ω_e·(L·i_d + λ_m),  where λ_m = K_t / (1.5·p)

Each axis then reduces to G(s) = 1/(L·s + R). Choose the PI zero to cancel the plant pole:

  C(s) = K_p + K_i/s,  with K_p = L·ω_c,i  and  K_i = R·ω_c,i

The open loop becomes ω_c,i/s, so the closed loop is first-order with bandwidth ω_c,i.

Sampling and PWM update add a delay of about 1.5·T_s. To keep phase margin ≥ 60°, limit the bandwidth:

  ω_c,i ≤ 1/(4.5·T_s) ≈ 4.4 krad/s at 20 kHz

The design uses ω_c,i = 2π·1500 ≈ 9.4 krad/s.
