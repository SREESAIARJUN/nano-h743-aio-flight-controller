# 3-Axis Gimbal: FOC, Cascaded Control, Anti-Cogging, and Dual-IMU Vibration Rejection

I don't have the original Job #3 specification, so this design is built on the assumptions in §0. Every hardware-dependent constant is a named parameter in one config struct, so you can substitute your real values without touching the algorithms.

---

## 0. Assumptions and Timing Architecture

| Item | Assumed value |
|---|---|
| MCU | STM32G474 class (Cortex-M4F, single-precision FPU, CORDIC optional) |
| Motors | 12N14P gimbal BLDC, 7 pole pairs, R ≈ 5–15 Ω, L ≈ 2–5 mH |
| Rotor sensor | 14-bit absolute magnetic encoder (AS5048A / MT6701), SPI |
| Current sense | 2-shunt or 3-shunt low-side, synchronised ADC |
| IMUs | 2 × ICM-42688-P on the camera plate, SPI @ 24 MHz, DMA, ODR = 8 kHz |
| Kinematics | Yaw → Roll → Pitch (outer to inner) |

### Loop rates

```
PWM center ISR    20 kHz  : ADC currents → Clarke/Park → d/q current PI → SVPWM
Velocity task      8 kHz  : IMU DMA complete → fusion → notch/LPF → velocity PI (+ cogging FF)
Angle task         1 kHz  : Mahony attitude → joint-space angle error → angle P/PI
Background         —      : cogging calibration, telemetry, fault handling
```

The velocity loop runs on the IMU data-ready interrupt (8 kHz). The rate measurement is therefore fresh on every execution and group delay is minimised.

## 1. Field-Oriented Control (Inner Current Loop)

### 1.1 Electrical model (surface PMSM, L_d = L_q = L)

$$
v_d = R\,i_d + L\frac{di_d}{dt} - \omega_e L\, i_q,\qquad
v_q = R\,i_q + L\frac{di_q}{dt} + \omega_e L\, i_d + \omega_e \lambda_m
$$

$$
\tau_e = \tfrac{3}{2} p\,\lambda_m\, i_q = K_t\, i_q,\qquad \theta_e = p\,\theta_m - \theta_{\text{off}},\qquad \omega_e = p\,\omega_m
$$
