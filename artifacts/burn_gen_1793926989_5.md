# FOC Motor Control and Dual-IMU Sensor Fusion for a 3-Axis Gimbal (Job #35)

I don't have the Job #35 specification, so this design is built on the assumptions below. Every assumption is a named constant in the code, so you can swap in the real values.

## 0. Assumptions and Architecture

| Item | Assumed value |
|---|---|
| MCU | STM32G474 class (Cortex-M4F, 170 MHz, hardware FPU) |
| Motors | 3× gimbal BLDC, 12N14P (pole pairs p = 7), R ≈ 5–10 Ω, L ≈ 2–4 mH |
| Position sensor | 14-bit absolute magnetic encoder per axis (AS5048A / MT6701) |
| Current sense | 2-phase low-side shunts (voltage mode is supported as a fallback) |
| IMU A | ICM-42688-P on the **camera/payload** (attitude and rate feedback) |
| IMU B | ICM-42688-P on the **base/handle** (disturbance feedforward and vibration reference) |
| Kinematics | Outer yaw q₁ (z), middle roll q₂ (x), inner pitch q₃ (y) |

**Loop rates and timing hierarchy.** Each loop has about 4–10× bandwidth separation from the one inside it.

```
 20 kHz  PWM ISR      : ADC → Clarke/Park → current PI → SVPWM   (BW_i  ≈ 1.5 kHz)
  8 kHz  IMU DRDY ISR : SPI burst ×2 → scale → AAF/notch/ANF chain
  4 kHz  Velocity     : rate PI + cogging FF + base-rate FF       (BW_ω  ≈ 150 Hz)
  1 kHz  Attitude     : Mahony fusion → angle P → rate setpoints  (BW_θ  ≈ 30 Hz)
```

## 1. Field-Oriented Control (Inner Current Loop)

### 1.1 Electrical angle with latency compensation

$$\theta_e = p\,(\theta_m - \theta_{\text{off}}) + p\,\hat\omega_m T_d,\qquad T_d \approx 1.5\,T_{PWM}$$

The term p·ω̂ₘ·T_d compensates the one-period computation delay plus the half-period PWM update delay.
