# FOC Motor Control and Dual-IMU Sensor Fusion for a 3-Axis Gimbal

I don't have the Job #22 specification, so this design is built on the stated assumptions below. Every hardware-dependent number is a named constant, so you can substitute your own values.

## 0. Baseline Assumptions

| Item | Assumed value |
|---|---|
| Motor | Gimbal BLDC, 12N14P (GBM2804-class). Pole pairs p = 7, slots Nₛ = 12. Rₛ ≈ 10 Ω, Lₛ ≈ 2.5 mH, K_t ≈ 0.08 N·m/A |
| Rotor sensor | 14-bit absolute magnetic encoder (AS5048A/MT6835-class) on each axis |
| MCU | STM32G4/H7-class with FPU, center-aligned PWM, ADC triggered at the PWM valley |
| IMU A (payload) | ICM-42688-P on the camera plate, SPI at 24 MHz, ODR 8 kHz |
| IMU B (base) | ICM-42688-P on the handle/airframe mount, SPI, ODR 8 kHz |
| Loop rates | Current 20 kHz · Rate (velocity) 4 kHz · Angle 1 kHz · Attitude estimator 4 kHz |
| Axis order | Base → Yaw → Roll → Pitch → Camera |

## 1. Field-Oriented Control (Inner Current Loop, 20 kHz)

### 1.1 Transforms

The electrical angle is computed from the mechanical angle and a calibrated electrical offset θ_off:

$$\theta_e = p\,\theta_m - \theta_{off}$$

**Clarke transform** (amplitude-invariant, assuming i_a + i_b + i_c = 0):

$$i_\alpha = i_a,\qquad i_\beta = \tfrac{1}{\sqrt3}\,(i_a + 2 i_b)$$

**Park transform:**

$$\begin{bmatrix} i_d\\ i_q\end{bmatrix}=\begin{bmatrix}\cos\theta_e & \sin\theta_e\\ -\sin\theta_e & \cos\theta_e\end{bmatrix}\begin{bmatrix} i_\alpha\\ i_\beta\end{bmatrix}$$

The inverse Park transform is the transpose of this matrix.

### 1.2 Plant Model (Surface PMSM, L_d = L_q = L)

$$v_d = R i_d + L\dot i_d - \omega_e L i_q$$

$$v_q = R i_q + L\dot i_q + \omega_e L i_d + \omega_e\lambda_m$$

Here ω_e is the motor-relative electrical speed:

$$\omega_e = p(\dot\theta_m)$$

Note that this is the rotor speed relative to the stator. It is **not** the payload's inertial rate. This distinction matters in Section 4.

### 1.3 PI Current Control with Decoupling and Back-EMF Feedforward

The control law is:

$$v_d^* = \mathrm{PI}_d(i_d^*-i_d) - \omega_e L i_q$$

$$v_q^* = \mathrm{PI}_q(i_q^*-i_q) + \omega_e L i_d + \omega_e\lambda_m$$

Choosing the gains as follows gives pole-zero cancellation:

$$K_p = L\,\omega_{c},\qquad K_i = R\,\omega_{c}$$

With these gains, the closed loop is first order:

$$\frac{i}{i^*} = \frac{\omega_c}{s+\omega_c}$$

Choose ω_c = 2π·1500 rad/s. This keeps ω_c below f_PWM/10 while leaving at least a 5× margin above the rate loop.

**Voltage limiting.** The voltage vector is limited to the linear SVPWM hexagon's inscribed circle:

$$|v| \le V_{dc}/\sqrt3$$

Under saturation, d-axis voltage gets priority:

$$v_{q,\max} = \sqrt{V_{max}^2 - v_d^{*2}}$$

The PI integrators use back-calculation anti-windup (Section 2.3).

### 1.4 SVPWM (Min-Max Zero-Sequence Injection)

$$v_{a,b,c}=\text{invClarke}(v_\alpha,v_\beta),\qquad v_0 = -\tfrac12\big(\max(v_{abc})+\min(v_{abc})\big)$$

$$d_x = \tfrac12 + \frac{v_x + v_0}{V_{dc}},\qquad x\in\{a,b,c\}$$

This is mathematically equivalent to sector-based SVPWM and avoids branching.
