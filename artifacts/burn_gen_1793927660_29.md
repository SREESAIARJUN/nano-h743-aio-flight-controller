# STM32H743 Flight Controller + 4-in-1 ESC (Nano Form Factor): Loss Model, Thermal Model, Bidirectional DShot600 DMA Plan, and Reference Netlist

**Job #31, Architecture Design Package, Rev A (preliminary)**

## 0. Architecture Clarification and Key Findings

**Architecture.** ArduPilot does not perform motor commutation. Bidirectional DShot therefore implies a split architecture:

- **Flight controller:** an STM32H743 running ArduPilot generates DShot600 frames and decodes eRPM telemetry.
- **4-in-1 ESC:** four dedicated ESC MCUs run the commutation firmware. This design assumes AT32F421 or STM32G071 class parts running AM32 or BLHeli_32. Each ESC MCU drives a 3-phase gate driver and six MOSFETs, switching at 48 kHz.

All analysis below assumes this split. If the intent was to have the H743 commutate the motors directly (for example using HRTIM), that is a different firmware project, and ArduPilot DShot would not apply.

**Feasibility findings.** These come from the calculations in Sections 1–3:

| Finding | Value | Implication |
|---|---|---|
| Loss per channel at 80 A, hot | ≈ 20 W | Achievable per channel, but only as a burst |
| Board loss with all 4 channels at 80 A | ≈ 80 W | Exceeds what a nano PCB can hold for more than ~3–4 s |
| Battery current at 4 × 80 A, D ≈ 0.9 | ≈ 290 A | Unrealistic for nano connectors and pads; the input path must be rated for it |
| Thermally sustainable continuous current | ≈ 25–30 A per channel | Matches what real nano 4-in-1 boards are rated for |

**Recommendation.** Specify the board as **"80 A burst (≤ 2 s, single or dual motor), ~30 A continuous per channel."** Enforce this in firmware with a current-time (I²t) limit.

All component parameters below are representative placeholders. Every number marked **[DS]** must be replaced with values from the datasheet of the selected part before the design is frozen.
