# FOC Control Loop and Dual-IMU Sensor Fusion for a 3-Axis Gimbal

I have no access to the Job #34 specification, so this design rests on the explicit assumptions in §0. Every equation is written so that you can substitute your real motor and IMU parameters. Where an assumption drives a design choice, the text says so.

## 0. Baseline Assumptions and Timing Architecture

| Item | Assumed value | Notes |
|---|---|---|
| Motor | Gimbal BLDC, 12N14P (p = 7 pole pairs), R ≈ 5–12 Ω, L ≈ 1–3 mH | Example: GBM2804-class |
| Encoder | 14-bit absolute magnetic (AS5048A / MT6701) on each joint | |
| MCU | STM32G4 / H7 class, single-precision FPU | |
| Current loop | 20 kHz, center-aligned PWM, 2- or 3-shunt sensing | |
| IMU | 2 × ICM-42688-P on the camera plate, ODR 8 kHz, gyro ±500 dps | |
| Velocity loop | 4 kHz, using **inertial** rate from the IMU | |
| Attitude/angle loop | 1 kHz | |
| Anti-cogging | Fourier harmonic feedforward, injected at the current-loop rate | |

**Bandwidth separation rule.** Each outer loop must be at least 4–5× slower than the loop inside it:

$$\omega_c^{(i)} \gtrsim 5\,\omega_c^{(v)} \gtrsim 25\,\omega_c^{(\theta)}$$

Typical values: current-loop crossover ≈ 2π·1.5 kHz, velocity ≈ 2π·150–250 Hz, angle ≈ 2π·30–50 Hz. In practice the velocity bandwidth is limited by the first structural resonance of the camera arm. Identify that resonance with a chirp test before you set the final gains.
