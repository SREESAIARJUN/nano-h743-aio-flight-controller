# 3-Axis Gimbal FOC Control & Dual-IMU Sensor Fusion: Design Specification

I don't have the original specification for Job #47, so this design is built on the assumptions below. Every numeric value is a parameter, so you can substitute your real hardware values without changing the structure.

| Item | Assumed value |
|---|---|
| MCU | STM32G474 / H7 class with FPU, CORDIC optional |
| Motors | Gimbal BLDC, 12N14P (pole pairs `p = 7`), R ≈ 5–15 Ω, L ≈ 2–5 mH |
| Rotor encoder | 14-bit absolute (AS5048A / MT6701), read at 20 kHz |
| PWM / current loop | 20 kHz center-aligned, current loop runs every PWM period |
| Velocity loop | 4 kHz (÷5) |
| Angle / attitude loop | 1 kHz (÷20) |
| IMUs | 2× ICM-42688-P on SPI, ODR = 8 kHz gyro and accel, FIFO or DRDY-driven |
| Mounting | Both IMUs on the camera plate at known lever arms `r₁` and `r₂`, arbitrary orientations `R₁` and `R₂` |

## 1. Field-Oriented Control (Innermost Loop, 20 kHz)

### 1.1 Electrical Angle

$$\theta_e = p\,(\theta_m - \theta_{\text{off}}) \bmod 2\pi$$

`θ_off` is found at commissioning: inject `v_d = V_align` with `θ_e = 0` and record `θ_m`.

### 1.2 Clarke and Park Transforms

The amplitude-invariant form, with `i_a + i_b + i_c = 0`, is:

$$i_\alpha = i_a,\qquad i_\beta = \tfrac{1}{\sqrt3}(i_a + 2 i_b)$$

$$\begin{bmatrix} i_d\\ i_q\end{bmatrix}=\begin{bmatrix}\cos\theta_e & \sin\theta_e\\ -\sin\theta_e & \cos\theta_e\end{bmatrix}\begin{bmatrix} i_\alpha\\ i_\beta\end{bmatrix}$$

### 1.3 Plant Model and Current PI

The dq-frame plant is:

$$v_d = R i_d + L\dot i_d - \omega_e L i_q,\qquad v_q = R i_q + L\dot i_q + \omega_e L i_d + \omega_e \lambda_m$$

**Tuning by pole-zero cancellation.** Choose the target current bandwidth `ω_c`, typically 2π·1.5 kHz, at or below `f_PWM/10`:

$$K_{p,i} = L\,\omega_c,\qquad K_{i,i} = R\,\omega_c$$

This makes the closed loop first-order: `I(s)/I*(s) = ω_c/(s+ω_c)`.

**Decoupling and back-EMF feedforward:**

$$v_d^* = \text{PI}_d(i_d^*-i_d) - \hat\omega_e \hat L i_q,\qquad v_q^* = \text{PI}_q(i_q^*-i_q) + \hat\omega_e(\hat L i_d + \hat\lambda_m)$$

**Voltage-mode fallback.** Gimbal motors often lack current shunts. If yours do, drop the PI loops and use:

$$v_q^* = R\,i_q^* + \omega_e\lambda_m$$

The rest of this design is unchanged.

### 1.4 Discrete PI with Back-Calculation Anti-Windup

$$u_k = K_p e_k + I_k,\qquad \bar u_k = \text{sat}(u_k)$$

$$I_{k+1} = I_k + K_i T_s e_k + K_{aw}(\bar u_k - u_k),\qquad K_{aw}\approx \frac{K_i}{K_p}\,T_s \cdot 2$$

The dq voltage vector is circle-limited:

$$|v_{dq}| \le V_{dc}/\sqrt3$$

`d` has priority, and `q` gets the remaining voltage, `√(V_max² − v_d²)`.

### 1.5 SVPWM (Min-Max Zero-Sequence Injection)

$$v_{a,b,c} = \text{invClarke}(\text{invPark}(v_d,v_q,\theta_e))$$

$$v_0 = -\tfrac12[\max(v_{abc}) + \min(v_{abc})]$$

$$d_x = \tfrac12 + \frac{v_x + v_0}{V_{dc}}$$

This is mathematically identical to sector-based SVPWM and is branch-light.

## 2. Cascaded Velocity / Angle Control

### 2.1 Mechanical Plant per Axis

$$J\dot\omega = K_t i_q - B\omega - \tau_{\text{cog}}(\theta_m) - \tau_{\text{dist}},\qquad K_t = \tfrac32 p\lambda_m$$
