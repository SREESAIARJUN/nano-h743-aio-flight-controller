# 3-Axis Gimbal: FOC Control Loop, Anti-Cogging Feedforward, and Dual-IMU Vibration Rejection

I don't have the original "Job #7" specification, so this design rests on the assumptions in §0. Every numeric parameter is collected in one config block so you can substitute your real values.

---

## 0. Assumptions and Loop Architecture

| Item | Assumed value | Notes |
|---|---|---|
| Motor | Gimbal BLDC, 12N14P (e.g. GBM2804-class) | Ns = 12 slots, p = 7 pole pairs |
| Phase R, L | R ≈ 5 Ω, L ≈ 1.2 mH (phase) | **Measure these** |
| Torque constant | K_t ≈ 0.06 N·m/A | **Measure this** |
| Encoder | 14-bit magnetic (AS5048A / MT6701) | Read over SPI each PWM cycle |
| MCU | Cortex-M4F/M7 with FPU, ≥168 MHz | |
| IMUs | 2× ICM-42688-P on the camera plate, SPI | IMU B is rotated relative to IMU A |
| Bus voltage | 12–16 V | |

**Loop rates and bandwidth separation**

```
 PWM / current loop (FOC)   : 20 kHz   bandwidth ω_c ≈ 2π·1.5 kHz
 IMU sampling + filters     :  8 kHz   (ICM-42688-P ODR)
 Velocity (rate) loop       :  4 kHz   bandwidth ω_v ≈ 2π·60 Hz
 Angle (attitude) loop      :  1 kHz   bandwidth ω_θ ≈ 2π·10 Hz
 Attitude estimator (Mahony):  1 kHz
```

Each outer loop runs at roughly 1/5 to 1/10 of the bandwidth of the loop inside it. That separation lets each loop treat the inner one as unity gain when you tune it.

**Signal flow for one axis**

```
θ_ref ─►(+)─► Angle P(+I) ─► ω_ref ─►(+)─► Velocity PI(D) ─► i_q,fb ─►(+)─► i_q* ─► FOC current PI ─► SVPWM ─► Motor
        ▲-                    ▲+ ω_ff   ▲-                     │        ▲+                              │
        │                     │         │                      │   i_q,cog (anti-cogging FF, LMS) ◄── θ_m (encoder)
   θ̂ (Mahony, fused IMUs)            ω̂ (fused gyro → notch → LPF)  └
