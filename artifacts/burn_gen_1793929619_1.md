# 3-Axis Gimbal: FOC Motor Control, Cascaded Control, Anti-Cogging, and Dual ICM-42688-P Fusion

I don't have the Job #32 spec sheet, so this design uses the assumptions below. Every parameter is a named constant, so you can substitute the real motor, encoder and MCU values without changing the structure.

## 0. Assumptions and Rate Plan

| Item | Assumed value |
|---|---|
| Motor | 12N14P gimbal BLDC (GBM2804-class), p = 7 pole pairs, R ≈ 10 Ω (phase), L ≈ 2.5 mH, λ ≈ 6 mWb |
| Encoder | AS5048A/MT6835-class absolute magnetic, ≥14-bit, SPI |
| Driver | 3× half-bridge (e.g., DRV8313), 3-shunt low-side current sense |
| MCU | STM32G4 / H7 (FPU, CORDIC optional), 170+ MHz |
| IMUs | 2× ICM-42688-P on the camera plate, SPI @ 24 MHz, gyro ODR 8 kHz |

| Loop | Rate | Target bandwidth |
|---|---|---|
| Current (d/q PI) | 20 kHz | ω_c ≈ 2π·1.5 kHz |
| Velocity (PI + cogging FF) | 4 kHz | ω_v ≈ 2π·150 Hz |
| Angle (P + rate FF) | 1 kHz | ω_θ ≈ 2π·30 Hz |
| IMU fusion + filtering | 8 kHz in, 4 kHz out | — |
| Attitude (Mahony) | 1 kHz | — |

Keep a separation of at least ×5 between nested loop bandwidths. The rest of the design depends on that.

## 1. FOC Equations

### 1.1 Electrical angle

$$\theta_e = p\,(\theta_m - \theta_{\text{off}}) \bmod 2\pi$$

θ_off is found at startup. Apply v_d = V_align with θ_e = 0, wait for the rotor to settle, then record θ_m.
