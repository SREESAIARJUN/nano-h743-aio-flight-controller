# 3-Axis Gimbal: FOC Control Loop and Dual-IMU Sensor Fusion

I have no specification for Job #17, so this design is built on the assumptions listed in §0. Every assumption is a named constant in the code. Replace them with your measured motor, encoder, and inertia values before tuning.

## 0. Assumed Hardware and Loop Rates

| Item | Assumption |
|---|---|
| MCU | STM32G4 / STM32H7 class with FPU, ≥170 MHz |
| Motors | Gimbal BLDC (GBM2804 class): 12N14P, pole pairs p = 7, R ≈ 5–10 Ω, L ≈ 1–3 mH |
| Encoder | 14-bit absolute magnetic (AS5048A / MT6701) over SPI, read each PWM cycle |
| Current sense | Two-shunt in-line or low-side, sampled at PWM center |
| IMUs | 2 × ICM-42688-P on the camera plate, mounted symmetrically about the camera centre, SPI at 24 MHz |
| PWM | 20 kHz center-aligned. The current loop runs at 20 kHz (Tₛc = 50 µs) |
| Velocity loop | 4 kHz (Tₛv = 250 µs) |
| Attitude / angle loop | 1 kHz (Tₛa = 1 ms) |
| IMU ODR | 8 kHz, decimated to 4 kHz after filtering |

**Timing hierarchy:**

```
TIM1 update (20 kHz)  ──► ADC inject ──► CurrentLoop ISR (FOC)          [prio 0]
                                │ every 5th ──► VelocityLoop             [prio 1]
IMU DRDY (8 kHz, x2)  ──► SPI DMA ──► ImuFrontEnd (notch/LPF/fusion)   [prio 1]
                                │ every 8th ──► AttitudeLoop (1 kHz)     [prio 2]
Background            ──► Cogging LMS adaptation, notch retuning, telemetry
```

## 1. Field-Oriented Control (Inner Current Loop)

### 1.1 Electrical Angle and Delay Compensation

Mechanical angle θₘ comes from the encoder, with offset θ_off found by alignment.

$$\theta_e = p\,(\theta_m - \theta_{off}) \bmod 2\pi$$

The PWM update lags the sample by about 1.5 Tₛc: half a cycle for the ADC-to-compute delay and one cycle for the PWM shadow register. The angle used for the *inverse* Park transform is therefore predicted forward:

$$\theta_e^{inv} = \theta_e + \omega_e \cdot 1.5\,T_{sc}, \qquad \omega_e = p\,\omega_m$$
