# FOC Motor Control and Dual-IMU Sensor Fusion for a 3-Axis Gimbal (Job #37)

I don't have the Job #37 specification, so this design states its assumptions explicitly (§0). Every motor- or board-specific number lives in one config struct. Swap in your real values and the gain formulas recompute automatically.

---

## 0. Assumptions and System Architecture

| Item | Assumed value | Notes |
|---|---|---|
| Motors | 3× gimbal BLDC, 12N14P (pole pairs `p = 7`) | e.g. GBM2804/GM3506 class |
| Phase R / L | ~5–10 Ω / 1.5–3 mH | Measure per motor |
| Encoder | 14-bit absolute magnetic (MT6701 / AS5048A) over SPI | One per joint |
| Current sensing | Low-side shunts on 2 phases | Sampled center-aligned |
| MCU | STM32G474 / H7 class, single-precision FPU | CORDIC optional |
| PWM | 20 kHz center-aligned | |
| IMUs | 2× ICM-42688-P on the camera plate | SPI, 8 kHz ODR, FIFO plus timestamps |

**Loop rates (all rates are integer divisors of PWM):**

```
 20 kHz   ADC ISR:  Clarke → Park → d/q current PI → inverse Park → SVPWM
  4 kHz   Velocity PI (+ anti-cogging FF, PLL velocity estimator)
  8 kHz   IMU sample: dual-IMU consistency → adaptive notch → biquad LPF → fusion
  1 kHz   Attitude (Mahony) + angle P loop + setpoint shaping
```

**Cascade per axis:**

```
θ_ref ─► [Angle P + ω_ff] ─► ω_ref ─► [Velocity PI] ─► i_q,ref ─(+)─► [Current PI dq] ─► SVPWM ─► Motor
                                              ▲                ▲ i_q,cog (anti-cogging FF)
θ_meas: IMU attitude (stabilize)
