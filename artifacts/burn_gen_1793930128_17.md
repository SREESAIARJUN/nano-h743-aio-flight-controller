## 0. Architecture Decisions and Review Flags

Four findings constrain the rest of the design:

| # | Finding | Consequence |
|---|---|---|
| F1 | The STM32H743 cannot practically run four sensored-less FOC/6-step ESCs *and* ArduPilot. | The architecture is **H743 (ArduPilot) → DShot600 bidirectional → 4× ESC MCUs** (AT32F421K8U7 running AM32). The 48 kHz switching frequency is set in AM32 firmware, not on the H743. |
| F2 | 80 A burst per channel produces about 16–17 W of loss per channel, or about 66 W per board (§3). | Burst operation is possible only as a **time-limited transient** that relies on board thermal mass. Continuous operation will be roughly 25–35 A per channel, depending on airflow. |
| F3 | Twenty-four 5×6 mm MOSFETs plus the H743 do not fit a 20×20 mm "nano" footprint. | Use a **30.5×30.5 mm stack-mount, 8-layer, 2 oz board**. If 20×20 mm is mandatory, 3.3×3.3 mm FETs (≈1.5–2 mΩ) roughly double conduction loss, and 80 A burst should be removed from the specification. |
| F4 | Component parameters below are **representative of the device class**. | Before freezing the BOM, substitute values from the actual datasheet (R_DS(on)(T), Q_gd, Q_rr, Z_th). The model is written so those values can be dropped in directly. |

**Assumed operating point:** 6S LiPo at 25.2 V maximum. Each switch is one 40 V, 5×6 mm MOSFET with R_DS(on),25°C ≈ 0.75 mΩ @ V_GS = 10 V. Gate driver is FD6288Q-class (bootstrap, ~1.5 A source/sink).
