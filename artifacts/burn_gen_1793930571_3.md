# 3-Axis Gimbal Control Design: FOC, Cascaded Control, Anti-Cogging, and Dual ICM-42688-P Fusion

I don't have the Job #34 specification, so this design states its assumptions in §0. Every numerical parameter is a named constant you can replace with your actual plant data. Gains are derived from physical parameters rather than hand-tuned constants.

---

## 0. Assumptions and Loop Architecture

| Item | Assumed value |
|---|---|
| MCU | STM32G474 / H7 class (FPU, CORDIC optional), 170+ MHz |
| Motors | Gimbal BLDC, 12N14P (pole pairs p = 7), R ≈ 5–15 Ω, L ≈ 1–3 mH |
| Encoder | 14-bit absolute magnetic encoder (AS5048A / MT6701), SPI |
| IMUs | 2× ICM-42688-P on separate SPI buses, mounted on the camera plate |
| Bus | 2S–4S Li-ion (7.4–16.8 V), 3 low-side shunts or inline sense |

**Loop rates (multi-rate, time-scale separated):**

```
 20 kHz  PWM ISR      : current sampling, Clarke/Park, current PI, SVPWM
  8 kHz  IMU DRDY ISR : read both IMUs, filters, fusion → camera rate ω_c
  4 kHz  velocity loop: encoder PLL, cogging FF, velocity PI → i_q*
  1 kHz  angle loop   : attitude (Mahony), angle PI → ω*
```

**Bandwidth separation rule:** each loop should be at least 4–10× slower than the loop inside it:

$$
\omega_{c,i} \approx 2\pi\cdot 1500\ \text{rad/s},\quad
\omega_{c,\omega} \le \omega_{c,i}/6 \approx 2\pi\cdot 150,\quad
\omega_{c,\theta} \le \omega_{c,\omega}/5 \approx 2\pi\cdot 25
$$

## 1. Field-Oriented Control (Inner Current Loop)

### 1.1 Transforms

Clarke transform (amplitude-invariant, with $i_a+i_b+i_c=0$):

$$
i_\alpha = i_a,\qquad i_\beta = \frac{i_a + 2 i_b}{\sqrt3}
$$

Park transform, with electrical angle $\theta_e = p\,\theta_m - \theta_{\text{off}}$:

$$
\begin{bmatrix} i_d\\ i_q\end{bmatrix} =
\begin{bmatrix} \cos\theta_e & \sin\theta_e\\ -\sin\theta_e & \cos\theta_e\end{bmatrix}
\begin{bmatrix} i_\alpha\\ i_\beta\end{bmatrix}
