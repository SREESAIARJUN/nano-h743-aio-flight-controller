# 3-Axis Gimbal FOC Control and Dual-IMU Sensor Fusion Design

I don't have the Job #47 spec sheet, so this design is parameterized. It uses typical gimbal hardware, listed in §0. Replace those values with your actual motor, encoder and MCU figures. Every gain is derived from them, so nothing has to be hand-guessed.

---

## 0. Baseline Assumptions

| Item | Assumed value | Symbol |
|---|---|---|
| Motor | GBM2804-class, 12N14P (p = 7 pole pairs), R = 5.6 Ω (phase), L = 1.9 mH | R, L, p |
| Torque constant | 0.065 N·m/A (measure it) | K_t |
| Flux linkage | λ = 2K_t / (3p) | λ |
| Rotor + payload inertia (per axis) | 2.5×10⁻⁴ kg·m² | J |
| Encoder | 14-bit magnetic (MT6701/AS5047P), SPI | θ_m |
| MCU | STM32G474 @ 170 MHz, FPU + CORDIC | — |
| PWM / current loop | 20 kHz center-aligned, current loop at 20 kHz | T_c = 50 µs |
| Velocity loop | 4 kHz | T_v = 250 µs |
| Angle loop / attitude | 1 kHz | T_θ = 1 ms |
| IMUs | 2 × ICM-42688-P, ODR 8 kHz, ±2000 dps, ±16 g, mounted on the camera plate | — |

**Control architecture (per axis):**

```
                     1 kHz                         4 kHz                        20 kHz
θ_ref ─►(+)─► [Angle P + FF] ─ω_ref─►(+)─► [Velocity PI] ─iq_pi─►(+)─► iq_ref ─► [FOC current PI + SVPWM] ─► Motor
         ▲                             ▲                          ▲ iq_cog(θ_m)
         │ θ_cam (attitude)            │ ω_axis (fused gyro)      └── Anti-cogging feedforward
         └──────── Dual-IMU fusion ◄───┘                         θ_e = p·θ_m (encoder) ─► Park/inv-Park
```

The encoder is used only for commutation and the cogging map. The angle and velocity loops close on the camera-frame IMU, which is what we actually want to stabilize.
