# STM32H743 FC + 80 A 4-in-1 ESC Nano Stack: System Model (Job #50)

**Document status:** Engineering model and reference design, Rev A. **Every component parameter marked [A] is an assumption.** Substitute the actual datasheet values before release.

## 0. Architecture Clarification and Feasibility Summary

**Architecture.** The STM32H743 is the flight controller MCU. It does not commutate the motors. A production "FC + 4-in-1" nano stack has two parts:

```
┌──────────────────────────┐   DShot600 bidir ×4   ┌─────────────────────────────────┐
│ FC: STM32H743VIT6 @400MHz│ ─────────────────────▶│ 4× ESC MCU (AT32F421 / STM32G071)│
│ ArduPilot                │ ◀───── eRPM (GCR) ────│ running AM32 or BLHeli_32        │
└──────────────────────────┘                       │ 4× 3-phase driver + 24 MOSFETs   │
                                                   └─────────────────────────────────┘
```

**Feasibility.** The math below reaches the following conclusions:

| Result | Value |
|---|---|
| Loss per channel at 80 A, hot | ≈ 24 W |
| Loss for all four channels | ≈ 97 W |
| Adiabatic burst window, 20×20 board | ≈ 1.1–1.5 s |
| Sustainable continuous total, prop-wash cooled | ≈ 6–10 W, i.e. ~25–30 A per channel |
| Battery current at full-throttle burst | up to 320 A |

The battery current exceeds XT60 ratings (60 A continuous, ~180 A burst) and 12 AWG wire. Therefore **"80 A burst" is only defensible as a ≤1 s, single-digit-duty-cycle rating.** I recommend marketing it as "45 A continuous / 80 A 1 s burst" and enforcing that limit in firmware (Section 6).
