# Job #7: 3-Axis Gimbal FOC Control Loop and Dual-IMU Sensor Fusion

I don't have the Job #7 spec, so the design rests on the assumptions in §0. Every parameter that depends on them is a named constant in the code.

---

## 0. Assumptions

| Item | Value |
|---|---|
| Motors | Gimbal BLDC (GM4108-class): 24N22P, so pole pairs p = 11. R ≈ 10 Ω, L ≈ 4 mH, K_t ≈ 0.08 N·m/A |
| Rotor sensor | 14-bit absolute magnetic encoder (AS5048A / MT6701) on each joint |
| MCU | STM32G4/H7, single-precision FPU, center-aligned PWM at 20 kHz |
| Loop rates | Current (FOC) 20 kHz. Rate/velocity 4 kHz. Attitude 1 kHz. IMU ODR 8 kHz. |
| IMUs | Two ICM-42688-P on the camera plate, mounted with different orientations (redundancy and noise averaging) |
| Kinematics | Yaw (outer) → Roll → Pitch (inner). Camera attitude: R = R_z(ψ) R_x(φ) R_y(θ) |

**Architecture.** The velocity loop closes on the *inertial* rate of the camera (from the gyros), not on the encoder rate. This is what actually rejects base motion. The encoder handles commutation, cogging compensation and a fallback rate estimate.

```
 q_target ─► [Attitude P] ─ω_cmd─► [J⁻¹(φ,θ)] ─q̇_cmd─► [Rate PI + FF] ─i_q*─► [+ Cogging FF] ─► [FOC PI d/q] ─► SVPWM
              ▲ q̂ (Mahony)                         ▲ q̇_inertial = J⁻¹ ω_gyro                ▲ θ_m (encoder)
              │                                    │
 2× ICM-42688-P ─► align ─► fault-checked inverse-variance fusion ─► adaptive notch ─► biquad LPF
```
