# 3-Axis Gimbal: FOC Control Loop and Dual-IMU Sensor Fusion Design

> **Scope note:** I don't have the specification for "Job #20," so I've used representative gimbal hardware, listed in §0. Every equation is written symbolically. You only need to replace the parameter block with your own values. Items marked **⚠ verify** depend on datasheet tables or register maps that you must check against your silicon revision.

## 0. Assumed Hardware and Timing Budget

| Item | Assumption |
|---|---|
| Motors | Gimbal BLDC, 12N14P (pole pairs p = 7), R ≈ 10 Ω, L ≈ 2.5 mH, Kt ≈ 0.08 N·m/A |
| Encoder | 14-bit absolute magnetic (AS5048A / MT6701 class), SPI |
| MCU | STM32G474 (170 MHz, FPU, CORDIC), center-aligned PWM at 20 kHz |
| Current sense | 2-shunt or inline, sampled at PWM center |
| IMUs | 2× ICM-42688-P on the camera plate, SPI, ODR 8 kHz, ±2000 dps / ±16 g, **common CLKIN** (see §5.1) |

| Loop | Rate | Bandwidth target |
|---|---|---|
| Current (d/q PI) | 20 kHz | f_c ≈ 1.5–2 kHz |
| Velocity (PI + cogging FF) | 4 kHz | f_v ≈ 100–150 Hz |
| Angle / attitude (P + FF) | 1 kHz | f_θ ≈ 25–40 Hz |
| IMU acquisition + filtering | 8 kHz → decimated to 4 kHz | — |
| Attitude estimator | 1 kHz | — |

Each outer loop is placed **4–10× below** the loop inside it. This separation lets each inner loop be treated as unity gain when you design the loop around it.
