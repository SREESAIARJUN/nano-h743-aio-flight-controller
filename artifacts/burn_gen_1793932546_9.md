# FOC Motor Control and Dual-IMU Sensor Fusion for a 3-Axis Gimbal

I don't have the Job #38 specification, so I've used representative parameters for a camera gimbal. Every one of them is a named constant in the code. Please confirm or replace:

| Item | Assumed value |
|---|---|
| MCU | STM32G4 / H7-class, single-precision FPU, 3× motor channels |
| Motors | Gimbal BLDC, 12N14P (pole pairs p = 7), R ≈ 5–10 Ω, L ≈ 1–3 mH |
| Rotor sensor | 14-bit absolute magnetic encoder (AS5048A / MT6701 class) |
| IMUs | 2× ICM-42688-P on the camera plate, each on its own SPI bus, sampled at 8 kHz ODR |
| Loop rates | Current 20 kHz → Velocity 4 kHz → Attitude 1 kHz |

## 1. System Architecture

```
          ┌──────────────── 1 kHz ─────────────┐ ┌────── 4 kHz ──────┐ ┌──── 20 kHz ────┐
q_ref ──► │ Attitude PID (SO(3) error) → ω_c* │►│ J⁻¹ → q̇* per axis │►│ Velocity PI    │► iq* ─┐
          └───────────────▲────────────────────┘ └─────────▲─────────┘ └───────▲────────┘      │
                          │ q̂ (Mahony AHRS)                │ ω̂ joint (gyro→J⁻¹ ∥ encoder PLL)  │
              ┌───────────┴───────────┐                                                       ▼
 IMU A ──►    │ Notch(f_e,2f_e) → LPF │──► Dual-IMU fusion ──┘           cogging FF iq_ff(θ_m) ──►(+)
 IMU B ──►    │ Notch(f_e,2f_e) → LPF │                                                        │
              └───────────────────────┘                            id*=0 ─► Current PI + decoupling
                                                                            → inv-Park → SVPWM → PWM
```

**Bandwidth separation rule.** Each outer loop should be at least 5× slower than the loop inside it:
ω_c,cur ≈ 2π·1.5 kHz ≫ ω_c,vel ≈ 2π·150 Hz ≫ ω_c,att ≈ 2π·20 Hz.
