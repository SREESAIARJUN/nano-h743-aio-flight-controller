# FOC Motor Control and Dual-IMU Fusion for a 3-Axis Gimbal

## 0. Assumptions

I have no specification for Job #46, so this design rests on the assumptions below. Every value is a named constant in the code. Replace them with your hardware's figures before tuning.

| Item | Assumed value |
|---|---|
| Motor | GM4108-class gimbal BLDC: 24 slots (Q), 22 poles (p = 11 pole pairs), R = 5.6 Ω, L = 2.4 mH, λ = 0.019 V·s/rad |
| Encoder | 14-bit absolute magnetic encoder (AS5048A / MT6701), one per axis, sampled synchronously with the PWM |
| MCU | STM32G4/H7-class with FPU, centre-aligned PWM at 20 kHz |
| IMUs | 2 × ICM-42688-P on the camera plate, mounted symmetrically about the plate's rotation centre, read over SPI at ODR = 8 kHz |
| Loop rates | Current 20 kHz → Velocity 4 kHz → Attitude/angle 1 kHz |
| Gimbal order | Base → Yaw (z) → Roll (x) → Pitch (y) → Camera |

## 1. Control Architecture

```
               1 kHz                    4 kHz                   20 kHz
 q_ref ──►[Attitude P + ω_ff]──►[J⁻¹(θ)]──►[Velocity PI]──►(+)──►[Current PI + decoupling]──►SVPWM──►Motor
              ▲   camera ω_cmd   joint θ̇_cmd     ▲  iq_v       ▲ iq_ff        ▲  i_abc, θ_e
              │                                  │             │
   [Dual IMU fusion: notch+LPF+Mahony]     [encoder θ̇]   [Anti-cogging FF (LMS)]
```

The loops are separated in bandwidth by roughly 5–10×:

- Current loop: ω_c ≈ 2π·1500 rad/s
- Velocity loop: ω_v ≈ 2π·150 rad/s
- Attitude loop: ω_θ ≈ 2π·15–25 rad/s
