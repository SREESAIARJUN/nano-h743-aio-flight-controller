## 0. Baseline Assumptions

I don't have the Job #22 parameter sheet, so the design below is fully parametric. The defaults are typical gimbal values. Replace every value marked **[P]** with your measured or datasheet numbers before tuning.

| Item | Default **[P]** |
|---|---|
| MCU | STM32G474 @ 170 MHz (FPU, CORDIC available) |
| Motor | 12N14P gimbal BLDC, 7 pole pairs, R = 5.6 Ω, L = 2.1 mH (phase), Kt = 0.08 N·m/A |
| Encoder | 14-bit absolute magnetic (MT6701 / AS5048A) on each axis |
| PWM | 20 kHz center-aligned, 3 half-bridges, inline or low-side shunts |
| IMUs | 2 × ICM-42688-P on the camera (payload) plate, SPI @ 24 MHz |
| Axis order | Yaw (Z, base) → Roll (X) → Pitch (Y, payload) |
| Payload inertia | J ≈ 2–8 × 10⁻⁴ kg·m² per axis |

### Loop Rate Hierarchy

| Loop | Rate | Target bandwidth | Feedback |
|---|---|---|---|
| Current (i_d, i_q) | 20 kHz | 1.5–2 kHz | Phase shunts + encoder θ_e |
| Rate (velocity) | 4 kHz | 80–150 Hz | Gyro (payload) → joint rate via J⁻¹ |
| Angle (attitude) | 1 kHz | 15–30 Hz | Fused quaternion |
| IMU sample | 8 kHz ODR | — | FIFO-free direct read on DRDY |

Each loop should have a bandwidth at least 5–10× lower than the loop inside it. With that separation, the inner loop looks like unity gain to the outer one up to the outer crossover frequency.
