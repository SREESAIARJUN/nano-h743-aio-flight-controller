# 3-Axis Gimbal FOC Control Loop and Dual-IMU Sensor Fusion: Design Specification

I don't have Job #54's hardware details, so this design states its assumptions explicitly. Every assumption is a single constant in the code (`config.hpp`). Change the constants to match your BOM.

| Item | Assumed value |
|---|---|
| MCU | STM32G474 class (Cortex-M4F, 170 MHz, single-precision FPU, CORDIC optional) |
| Motors | Gimbal BLDC, 12N14P (pole pairs $p=7$), $R_s \approx 5\,\Omega$, $L_s \approx 2\,\text{mH}$, $K_t \approx 0.08$ N·m/A |
| Position sensor | 14-bit absolute magnetic encoder per axis (AS5048A / MT6701), read over SPI |
| Inertial sensors | 2 × ICM-42688-P on the camera plate, separate SPI buses with DMA, 8 kHz ODR |
| Kinematic order | Base → Yaw ($\psi$, z) → Roll ($\phi$, x) → Pitch ($\theta$, y) → Camera |
| Loop rates | Current 20 kHz · Velocity 4 kHz · Angle/attitude 1 kHz |

## 1. Control Architecture

```
            1 kHz                    4 kHz                    20 kHz
 q_ref ─►[Attitude err]─►θ_err─►[Angle P + FF]─►ω_ref─►[Velocity PI]─►iq_ref─►[Current PI + decoupling]─►SVPWM
              ▲                         ▲                    ▲   ▲               ▲
         Mahony AHRS ◄── fused gyro/acc │     joint rate ◄───┘   └─ iq_cog(θm) ── encoder θm
              ▲                         │     (Jacobian⁻¹·ω_gyro)     anti-cogging FF
   IMU A ─┐  notch+PT2                  │
          ├─►[inverse-variance fusion]──┘
   IMU B ─┘
```

**Bandwidth separation.** Each loop is at least 4–5× slower than the loop inside it:

$$\omega_{c,i} \approx 2\pi\cdot 1500\ \text{rad/s} \;>\; \omega_{c,v}\approx 2\pi\cdot 150 \;>\; \omega_{c,\theta}\approx 2\pi\cdot 25$$
