# STM32H743 FC + 4-in-1 80A ESC (Job #22): Architecture, Loss Model, BDShot DMA Plan, and Netlist

## 0. Review Findings

Three issues shape the rest of this document:

1. **The STM32H743 cannot be the ESC MCU.** ArduPilot runs on the H743 (flight controller). Each ESC channel needs its own commutation MCU running AM32 or BLHeli_32, such as an AT32F421 or STM32G071. A single H743 driving 12 FETs with sensorless commutation is not a supported or sane configuration. The design below is therefore **H743 FC + 4× AT32F421 ESC MCUs**.
2. **"80A" must be specified as a duration, not a number.** As computed in §3, a 4×80A burst dissipates about 100 W. On a 20×20 board that gives roughly 2 s of usable burst. On 30×30, roughly 4 s. Continuous capability is about 25–35A per channel with airflow. The datasheet must state "80A / Xs burst @ T_amb".
3. **The FET choice is not specified, so every number below rests on stated assumptions.** Replace the Table 1 values with the selected part's datasheet values and the model re-evaluates directly.

**Recommended form factor:** stacked 30.5×30.5 (FC on top, ESC below). An AIO with an H743 and 80A FETs on 20×20 is not thermally credible.

## 2. Conduction Loss Model

### 2.1 Topology

Each channel is a 3-phase bridge (6 FETs) using trapezoidal 6-step commutation with complementary (synchronous) PWM. During any 60° sector:

- **Leg A (PWM leg):** the high-side FET conducts for duty D, and the low-side FET synchronously rectifies for (1−D).
- **Leg B (return leg):** the low-side FET is fully on.

The current therefore always flows through exactly two R_DS(on) in series:

$$P_{cond,ch} = I^2\,(2R_{hot} + R_{sh} + R_{cu})$$

### 2.2 Temperature dependence

$$R_{hot} = R_{25}\,[1+\alpha(T_j-25)]$$

Because R_hot depends on T_j and T_j depends on loss, the loss and temperature must be solved together (see §4.3).

### 2.4 Per-FET distribution

Each FET is active for 120° of the 360° electrical cycle:

- **Electrical-cycle average per FET:** I²R_hot / 3 = **2.99 W**
- **Peak while active:** I²R_hot = **8.96 W**

For a 14-pole motor at 30k RPM, the electrical frequency is 3.5 kHz. That is far faster than the die thermal time constant (about 1–10 ms), so the per-FET average is the correct quantity for thermal design. At low eRPM (locked rotor or startup), use the peak value instead.
