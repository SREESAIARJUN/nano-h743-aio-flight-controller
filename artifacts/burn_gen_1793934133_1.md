# FOC Motor Control and Dual-IMU Fusion for a 3-Axis Gimbal

I don't have a "Job #7" specification, so this design rests on the assumptions below. Each one is a named constant in the code, so you can substitute your real values.

| Parameter | Assumed value |
|---|---|
| Motor | Gimbal BLDC, 12N14P (7 pole pairs), R = 5.6 Ω, L = 2.1 mH, λ = 0.0047 V·s/rad |
| Encoder | 14-bit absolute magnetic (AS5048A / MT6701 class) |
| MCU | Cortex-M4F/M7 with single-precision FPU (STM32G4/H7 class) |
| Bus voltage | 12 V |
| PWM / current loop | 20 kHz, center-aligned |
| Velocity loop | 10 kHz |
| Angle loop | 2 kHz |
| IMU | 2× ICM-42688-P on the camera plate, mirrored about the plate center, ODR 8 kHz |

## 1. Control Architecture

```
            IMU fusion (8 kHz)                 Encoder θm (20 kHz)
                 │ q̂, ω̂                              │
θ_ref ─►[Angle P + ω_ff]─► ω_ref ─►[Velocity PI]─► iq_ref ─(+)─►[Current PI d/q + decoupling]─► SVPWM
  2 kHz                       10 kHz          ▲    20 kHz
                                              │
                         iq_cog(θm) ◄─[Cogging Fourier FF + LMS]
```

The design has three layers:

- **Inner loop:** field-oriented current control, using the encoder electrical angle.
- **Middle loop:** velocity control. Feedback is the gyro-measured camera rate projected onto the joint axis, which gives inertial stabilization. When no IMU is available, it falls back to the encoder-derived velocity.
- **Outer loop:** attitude control on the fused quaternion error.

Each loop runs at least 5× slower in bandwidth than the loop inside it.

## 2. Field-Oriented Current Loop

### 2.1 Transforms

The electrical angle is the mechanical angle scaled by the pole-pair count, minus the encoder offset:

$$\theta_e = p\,\theta_m - \theta_{\text{off}}, \qquad p = 7$$

**Clarke transform** (balanced phases, so $i_a+i_b+i_c=0$):

$$i_\alpha = i_a, \qquad i_\beta = \frac{i_a + 2 i_b}{\sqrt3}$$

**Park transform:**

$$\begin{bmatrix} i_d \\ i_q\end{bmatrix}=\begin{bmatrix}\cos\theta_e & \sin\theta_e\\ -\sin\theta_e & \cos\theta_e\end{bmatrix}\begin{bmatrix} i_\alpha \\ i_\beta\end{bmatrix}$$

The inverse Park transform is the transpose of this matrix.

### 2.2 Plant and Decoupling

For a surface PMSM, $L_d = L_q = L$, and the d/q voltage equations are:

$$v_d = R i_d + L\dot i_d - \omega_e L i_q, \qquad v_q = R i_q + L\dot i_q + \omega_e (L i_d + \lambda)$$

Adding the feedforward terms below cancels the cross-coupling and back-EMF:

$$v_d^{ff} = -\omega_e L i_q, \qquad v_q^{ff} = \omega_e (L i_d + \lambda)$$

Each axis then behaves as a simple first-order plant:

$$G_i(s) = \frac{1}{Ls + R}$$

### 2.3 PI Tuning by Pole-Zero Cancellation

Choose the PI zero to cancel the electrical pole:

$$C_i(s) = K_p + \frac{K_i}{s}, \qquad K_p = L\,\omega_c,\quad K_i = R\,\omega_c$$

The closed loop then becomes a pure first-order response:

$$T(s) = \frac{\omega_c}{s + \omega_c}$$

With $f_c = 2$ kHz and $\omega_c = 2\pi \cdot 2000$, this gives $K_p = 26.4$ V/A and $K_i = 70{,}370$ V/(A·s).

$f_c$ is kept at or below $f_{pwm}/10$ so that the 1.5-sample computation and PWM delay costs less than 25° of phase margin.

### 2.4 Discretization and Anti-Windup

The PI is discretized with backward Euler, period $T_s$, and uses back-calculation anti-windup with gain $K_{aw} = 1/K_p$:

$$u_k = K_p e_k + I_k,\qquad u^{sat}_k = \text{sat}(u_k)$$

$$I_{k+1} = I_k + T_s\big[K_i e_k + K_{aw}^{-1}...\big]$$

In practice the code uses this equivalent form:

$$I_{k+1} = I_k + K_i T_s e_k + \tfrac{T_s}{T_t}\,(u^{sat}_k - u_k), \qquad T_t = \sqrt{T_i}, \;\; T_i = K_p/K_i$$

**Voltage vector saturation.** The voltage vector is limited to the linear region of SVPWM:

$$|v_{dq}| \le V_{bus}/\sqrt3$$

The d-axis gets priority. The q-axis receives whatever voltage remains:

$$v_q^{max} = \sqrt{V_{max}^2 - v_d^2}$$

### 2.5 SVPWM by Min-Max Injection

After the inverse Clarke transform gives $v_a, v_b, v_c$, inject the common-mode offset:

$$v_0 = -\tfrac12\big(\max(v_{abc}) + \min(v_{abc})\big)$$

The phase duties are:

$$d_x = \tfrac12 + \frac{v_x + v_0}{V_{bus}}$$

This is mathematically identical to sector-based SVPWM and is about 3× cheaper to compute.

## 3. Velocity and Angle Loops

### 3.1 Velocity Loop

The mechanical plant, with the current loop treated as unity gain inside the velocity bandwidth, is:

$$J\dot\omega = K_t i_q - B\omega - \tau_{cog}(\theta_m) - \tau_d$$

$$K_t = \tfrac32 p\lambda = 0.0494\ \text{N·m/A}$$

**Symmetric-optimum-style PI tuning** with crossover $\omega_v$ and separation factor $a$ (typically $a = 3\text{–}4$):

$$K_{pv} = \frac{J\,\omega_v}{K_t}, \qquad K_{iv} = K_{pv}\,\frac{\omega_v}{a^2}$$

With $J = 2.5\times10^{-4}$ kg·m² (camera plus arm about the axis) and $f_v = 150$ Hz:

- $K_{pv} = 4.77$ A/(rad/s)
