# FOC Motor Control and Dual-IMU Sensor Fusion for a 3-Axis Gimbal (Job #48)

## 0. Assumptions and Baseline Parameters

I don't have your Job #48 specification, so the design below rests on a typical direct-drive brushless gimbal. Every value marked **[cfg]** is a placeholder. Replace those values with your measured data before tuning.

| Item | Value |
|---|---|
| MCU | STM32G474 class (FPU, 170 MHz), center-aligned PWM |
| Motors | 3 × gimbal BLDC, 12N14P (pole pairs p = 7) **[cfg]** |
| Example motor constants | R_s = 5.6 Ω, L_s = 1.6 mH, K_t = 0.085 N·m/A **[cfg]** |
| Encoders | 14-bit absolute magnetic encoder (e.g., MT6701 / AS5047P) on each joint |
| IMUs | 2 × ICM-42688-P on SPI at 24 MHz, with UI ODR = 8 kHz |
| IMU_P placement | Camera plate. Provides attitude and inertial-rate feedback. |
| IMU_B placement | Base or handle. Provides the disturbance feedforward. |
| PWM / current loop | 24 kHz (T_c = 41.67 µs) |
| Velocity loop | 8 kHz (T_v = 125 µs), synchronized to the IMU data-ready interrupt |
| Angle loop + attitude fusion | 1 kHz (T_θ = 1 ms) |
| Gimbal order | Yaw (outer) → Roll → Pitch (inner, carries the camera) |

**Loop bandwidth hierarchy.** The current loop at roughly 2 kHz is faster than the velocity loop at roughly 150 Hz, which is faster than the angle loop at roughly 15 Hz. Each adjacent pair is separated by about 10×. This separation is what allows each loop to be designed as if the inner loop were ideal.
