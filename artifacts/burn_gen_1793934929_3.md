# 3-Axis Gimbal: FOC Motor Control and Dual-IMU Sensor Fusion

This document covers the high-frequency control loop and sensor fusion for Job #0.

## 0. Assumptions

I don't have the Job #0 spec sheet, so this design assumes the hardware below. Every parameter is a named constant, so you can change it in one place.

| Item | Assumed value |
|---|---|
| MCU | STM32G4 / H7 class: Cortex-M4F/M7, single-precision FPU, 170+ MHz |
| Motors | Gimbal BLDC, 12N14P (p = 7 pole pairs, N_s = 12 slots), R ≈ 5–12 Ω, L ≈ 1–3 mH |
| Rotor sensor | 14-bit absolute magnetic encoder (MT6701 / AS5047P) on each axis |
| Current sense | 2-phase low-side shunts, synchronous with PWM center |
| PWM | 20 kHz center-aligned. Current loop runs at 20 kHz. |
| IMUs | 2 × ICM-42688-P on the camera plate, SPI at 24 MHz, ODR 8 kHz |
| Loop rates | Current 20 kHz → Rate (velocity) 4 kHz → Attitude (angle) 1 kHz |
| Kinematics | Yaw (outer) → Roll → Pitch (inner, camera) |

Bandwidth separation rule: each outer loop's bandwidth is at most 1/5 to 1/10 of the inner loop's. Initial targets:

- ω_c (current): 2π·1500 rad/s
- ω_v (rate): 2π·150 rad/s
- ω_θ (angle): 2π·15 rad/s

## 1. Field-Oriented Control (Current Loop, 20 kHz)

### 1.1 Electrical angle

$$\theta_e = p\,(\theta_m - \theta_{\text{off}}) \bmod 2\pi$$

θ_off is found at calibration. Drive V_d > 0 with θ_e = 0, wait for the rotor to settle, then read θ_m.

The angle used for the inverse transform is compensated for one PWM period of computation delay plus the half-period ZOH delay:

$$\theta_{e,\text{comp}} = \theta_e + 1.5\,\omega_e T_s$$
