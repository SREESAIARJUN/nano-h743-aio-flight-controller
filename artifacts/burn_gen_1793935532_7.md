# 3-Axis Gimbal: FOC Control, Anti-Cogging, and Dual-IMU Vibration Rejection

## 0. Assumptions

I don't have the specification for Job #24, so the design below rests on stated assumptions. Every value is a named constant. Swap in your measured data and the equations still hold.

| Item | Assumed value |
|---|---|
| MCU | STM32G4-class Cortex-M4F @ 170 MHz, single-precision FPU |
| Motors | Gimbal BLDC, 12N14P (pole pairs P = 7), R ≈ 8 Ω, L ≈ 3 mH, Kt ≈ 0.08 N·m/A |
| Encoder | 14-bit absolute magnetic (AS5048A / MT6701), one per joint |
| IMUs | 2 × ICM-42688-P on the camera plate, mounted symmetrically about the payload's center of mass (r_B = −r_A) |
| Loop rates | Current 20 kHz · IMU 8 kHz · Velocity 4 kHz · Angle/attitude 1 kHz |
| Bus | Vbus = 12 V nominal, measured each cycle |

**Interpretation of "dual vibration rejection".** Both IMUs sit on the payload. Each passes through its own filter chain:
1. On-chip anti-aliasing filter (AAF).
2. Adaptive notch tracking the dominant vibration line.
3. Static notch for a known propeller/ESC line.
4. 2nd-order Butterworth low-pass.

The two chains are then fused with inverse-variance weighting and fault isolation. If your second IMU is on the base instead, the same filter classes apply. In that case, use it as a base-rate feedforward (§3.6).

### 1.1 Transforms

**Electrical angle with delay compensation.** PWM update plus sampling adds about 1.5 sample periods of delay:

$$\theta_e = P\,(\theta_m - \theta_{\text{off}}) + \omega_e \cdot 1.5\,T_i$$
