# FOC Control Loop and Dual-IMU Sensor Fusion for a 3-Axis Gimbal (Job #43)

I don't have the Job #43 spec sheet, so the design below rests on stated assumptions. Every motor- and frame-specific constant sits in one config struct. Substitute your measured values there, and the math and code remain valid.

## 0. Assumptions and Loop Architecture

| Item | Assumed value |
|---|---|
| Motors | Gimbal BLDC 12N14P (pole pairs p = 7), R ≈ 5–10 Ω, L ≈ 1–3 mH |
| Encoder | 14-bit absolute magnetic encoder (AS5048A / MT6701 class), SPI |
| MCU | Cortex-M4F/M7 with FPU (STM32G4 / H7 class), center-aligned PWM, inline/low-side current sense |
| IMUs | 2 × ICM-42688-P on the camera plate, SPI, ODR 8 kHz, ±2000 dps, ±16 g |
| Axis order | Base → **Yaw (z)** → **Roll (x)** → **Pitch (y)** → camera |

**Loop rates.** Each outer loop is 4–5× slower than the loop inside it.

```
 20 kHz  : current (FOC) loop      — PWM ISR, per motor
  8 kHz  : IMU sample + filters    — IMU data-ready ISR / DMA
  4 kHz  : velocity loop           — per motor, decimated /5
  1 kHz  : attitude/angle loop     — gimbal frame, decimated /20
```

```
θ*,ω* ─►[Angle P + FF]─ω_ref─►[Velocity PI + FF]─iq_ref─►(+)─►[Current PI dq + decoupling]─►invPark─►SVPWM─► Motor
            ▲ θ_cam (IMU)          ▲ ω (IMU gyro / enc)      ▲ iq_cog (anti-cogging LUT)   ▲ id,iq (Clarke/Park)
```
