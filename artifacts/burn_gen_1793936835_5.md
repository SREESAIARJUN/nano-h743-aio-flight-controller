# 3-Axis Gimbal: FOC Control Loop, Anti-Cogging, and Dual-IMU Fusion (Job #46)

## 0. Assumptions and Timing Architecture

I don't have the Job #46 hardware spec, so this design assumes the following. All parameters are centralized in `GimbalConfig`, so you can substitute your real values.

| Item | Assumed value |
|---|---|
| Motor | Gimbal BLDC, 12N14P (`P = 7` pole pairs), R ≈ 5–15 Ω, L ≈ 1–3 mH |
| Encoder | 14-bit absolute magnetic (AS5048A / MT6701 class) |
| MCU | STM32G4 / H7 class with FPU, center-aligned PWM |
| IMUs | 2 × ICM-42688-P on the camera plate, SPI, ODR 8 kHz |
| Bus | 12–16 V |

The control loops run at different rates, each triggered by a specific event:

| Loop | Rate | Trigger |
|---|---|---|
| Current (FOC) | 20 kHz | PWM-centered ADC ISR |
| IMU acquisition + filters | 8 kHz | IMU DRDY (both sensors, phase-aligned) |
| Rate (velocity) PI | 4 kHz | Every 2nd IMU sample |
| Attitude (angle) loop | 1 kHz | Scheduler |

Loop bandwidths are separated by a factor of 4–5 or more to keep the cascade stable:

> ω_i ≈ 2π·1.5 kHz, ω_v ≈ 2π·60–120 Hz, ω_θ ≈ 2π·10–25 Hz

**Gimbal-specific point:** the velocity loop is closed on the **inertial rate from the IMU**, projected onto the motor axis. The encoder is used for commutation, cogging compensation, and joint-limit handling. This arrangement is what produces stabilization rather than mere joint servoing.

## 1. FOC Current Loop

### 1.1 Transforms

The electrical angle is

$$\theta_e = P(\theta_m - \theta_{off}) \bmod 2\pi.$$

**Clarke transform** (amplitude-invariant, assuming i_a + i_b + i_c = 0):

$$i_\alpha = i_a,\qquad i_\beta = \tfrac{1}{\sqrt3}(i_a + 2i_b)$$

**Park transform:**

$$\begin{bmatrix}i_d\\ i_q\end{bmatrix}=\begin{bmatrix}\cos\theta_e & \sin\theta_e\\ -\sin\theta_e
