# Gimbal FOC Control Loop & Dual‑IMU Sensor Fusion: Design Specification

I don't have the Job #2 specification itself, so this design is built on the **stated assumptions in §0**. Every parameter that depends on your hardware is collected in one config struct, so you can substitute your real values.

---

## 0. Assumptions & Loop Architecture

| Item | Assumed value |
|---|---|
| Motors | 3× gimbal BLDC, 12N14P (pole pairs p = 7), low‑Kv, R ≈ 5 Ω, L ≈ 2 mH |
| Rotor sensor | 14‑bit absolute magnetic encoder (e.g. AS5048/MT6701) per axis |
| Bus | 12–16 V, 3‑phase driver with 2 or 3 low‑side shunts |
| IMUs | 2× ICM‑42688‑P on the camera plate, SPI, 8 kHz ODR, ±2000 dps, ±4 g |
| MCU | Cortex‑M4F/M7 (STM32G4/H7 class), single‑precision FPU |

**Loop rates:**

```
 20 kHz  Current loop (FOC: Clarke/Park, PI d/q, SVPWM)        ← PWM-center ADC ISR
  4 kHz  Velocity loop (inertial rate from fused gyro)          ← every 5th current ISR
  1 kHz  Attitude/angle loop + Mahony AHRS + anti-cog update
  8 kHz  IMU data-ready ISR: dual read, consistency check, notches
```

**Bandwidth separation rule (≥ 4–5× per stage):**

- Current loop: ω_c ≈ 2π·1500 rad/s.
- Velocity loop: ω_v ≈ 2π·60–100 rad/s. The limit comes from structural modes and the IMU filter delay.
- Angle loop: ω_θ ≈ ω_v/4.
