# Gimbal Motor Control and Sensor Fusion: FOC, Cascaded PID, Anti-Cogging, and Dual ICM-42688-P Filtering

I don't have the Job #29 specification, so this design uses the assumptions in §0. Every parameter is a named constant so you can substitute your real values.

## 0. Assumptions and Loop Architecture

| Item | Assumed value |
|---|---|
| Motor | BLDC gimbal motor, 12N14P (pole pairs p = 7), R ≈ 5 Ω, L ≈ 2 mH, K_t ≈ 0.08 N·m/A |
| Position sensor | 14-bit magnetic encoder (e.g., AS5047P/MT6835) on each motor shaft |
| IMUs | 2 × ICM-42688-P on the camera platform, SPI at 24 MHz, gyro/accel ODR 8 kHz |
| MCU | Cortex-M7 or M4F with FPU (STM32H7/G4 class) |
| PWM | 20 kHz center-aligned, with ADC sampling at the PWM midpoint |

**Loop rates.** Each loop has roughly 5–10× bandwidth separation from the next.

```
 20 kHz  Current (FOC) loop   BW ≈ 1.5 kHz   (encoder θe, phase currents)
  4 kHz  Velocity loop        BW ≈ 150 Hz    (fused gyro rate, IMU frame)
  1 kHz  Angle loop           BW ≈ 20 Hz     (fused attitude → joint error)
  8 kHz  IMU acquisition + vibration filters (decimated to 4 kHz)
```

**Signal flow per axis:**

```
θ_ref ─►(Σ)─► Angle P+FF ─► ω_ref ─►(Σ)─► Velocity PI(D) ─► τ_ref ─► ÷Kt ─► i_q,ref ─►(Σ)─► FOC ─► SVPWM ─► Motor
         ▲                            ▲                              ▲
   θ_imu (fused attitude)       ω_imu (fused, filtered gyro)   i_q,cog(θm) anti-cogging FF
```

The outer loops close on the **camera-frame IMU** quantities, because what you are stabilizing is the camera. The **encoder** is used only for commutation and the cogging lookup.

## 1. Field-Oriented Current Control

### 1.1 Transforms

Electrical angle, with encoder offset θ_off measured at calibration:

$$\theta_e = p\,\theta_m - \theta_{off} \pmod{2\pi}$$

The Clarke transform is amplitude invariant. Only two phases are measured, using i_a + i_b + i_c = 0:

$$i_\alpha = i_a,\qquad i_\beta = \frac{1}{\sqrt3}(i_a + 2 i_b)$$

Park transform:

$$\begin{bmatrix} i_d\\ i_q\end{bmatrix} = \begin{bmatrix}\cos\theta_e & \sin\theta_e\\ -\sin\theta_e & \cos\theta_e\end{bmatrix}\begin{bmatrix} i_\alpha\\ i_\beta\end{bmatrix}$$

Inverse Park transform:

$$v_\alpha = v_d\cos\theta_e - v_q\sin\theta_e,\qquad v_\beta = v_d\sin\theta_e + v_q\cos\theta_e$$

### 1.2 Plant and PI design

The surface-mount PMSM model in the dq frame is:

$$v_d = R i_d + L\dot i_d - \omega_e L i_q,\qquad v_q = R i_q + L\dot i_q + \omega_e L i_d + \omega_e\lambda_m$$

To make the plant a first-order lag, add decoupling and back-EMF feedforward:

$$v_d = \mathrm{PI}_d(e_d) - \omega_e L i_q,\qquad v_q = \mathrm{PI}_q(e_q) + \omega_e L i_d + \omega_e \lambda_m$$

Pole-zero cancellation with target bandwidth ω_c (rad/s) gives a closed loop of ω_c/(s+ω_c):

$$K_p = L\,\omega_c,\qquad K_i = R\,\omega_c$$

Here λ_m is the PM flux linkage, with K_t = (3/2) p λ_m. Pick ω_c ≤ 2π f_pwm/10 to account for the one-sample computation delay plus the PWM hold. At 20 kHz, ω_c = 2π·1500 rad/s.

### 1.3 Discretization and anti-windup

Use forward-Euler integration with sample time T_s, plus clamping-type anti-windup. Clamping matters here: the voltage vector is limited, and the q-axis takes priority.

$$u_k = K_p e_k + I_k,\qquad I_{k+1} = I_k + K_i T_s e_k \quad\text{only if not }(\text{saturated} \wedge \text{sign}(e_k)=\text{sign}(u_k))$$

The voltage limit comes from the inscribed circle of the SVPWM hexagon:

$$|v_{dq}| \le V_{max} = \frac{V_{bus}}{\sqrt3}\cdot m_{max}, \quad m_{max}\approx 0.95$$

Allocation order:
1. v_d gets up to V_max.
2. v_q gets up to $\sqrt{V_{max}^2 - v_d^2}$.

### 1.4 SVPWM (min-max zero-sequence injection)

$$v_a = v_\alpha,\quad v_b = -\tfrac12 v_\alpha + \tfrac{\sqrt3}{2}v_\beta,\quad v_c = -\tfrac12 v_\alpha - \tfrac{\sqrt3}{2}v_\beta$$

$$v_0 = -\tfrac12(\max(v_{abc}) + \min(v_{abc})),\qquad D_x = \tfrac12 + \frac{v_x + v_0}{V_{bus}}$$

This is mathematically equivalent to sector-based SVPWM and is branch-light.

## 2. Cascaded Angle/Velocity Control

### 2.1 Mechanical plant (per axis, decoupled approximation)

$$J\dot\omega = K_t i_q - B\omega - \tau_{cog}(\theta_m) - \tau_{dist}$$

The full gimbal is coupled. Each joint's inertia J depends on the downstream joint angles. If you gain-schedule on the measured joint angles, J_yaw(θ_roll, θ_pitch) can be precomputed from CAD. The equations below use J as the scheduled value.

### 2.2 Velocity loop (PI + filtered D on measurement + feedforward)

$$\tau_{ref} = K_{pv} e_\omega + K_{iv}\!\int e_\omega\,dt - K_{dv}\,\dot{\omega}_f + J\,\dot\omega_{ref}$$

with e_ω = ω_ref − ω_imu.

**Derivative on measurement.** The derivative acts on ω_imu, not on the error, so setpoint steps don't kick. It is low-passed with a time constant τ_d = 1/(2π f_d), Tustin-discretized:

$$D_k = \frac{2\tau_d - T_s}{2\tau_d + T_s} D_{k-1} - \frac{2K_{dv}}{2\tau_d + T_s}(\omega_k - \omega_{k-1})$$

**Gain design.** For a velocity bandwidth ω_v and an integrator corner at ω_v/4:

$$K_{pv} = J\,\omega_v,\qquad K_{iv} = K_{pv}\,\frac{\omega_v}{4}$$

The D term is optional, typically ≤ 0.1·J. It helps damp the structural mode of the camera arm.

**Back-calculation anti-windup.** Here τ_sat is the clamped output and K_aw ≈ K_iv/K_pv:

$$I_{k+1} = I_k + T_s\left[K_{iv}e_k + K_{aw}(\tau_{sat} - \tau_{ref})\right]$$

### 2.3 Angle loop (P + velocity feedforward)

$$\omega_{ref} = K_{pa}\,\mathrm{wrap}_{\pi}(\theta_{ref} - \theta_{imu}) + \dot\theta_{ref}, \qquad K_{pa} = \omega_a \approx \omega_v/6$$

A small K_ia can be added to remove steady-state error against a constant unbalance torque. The velocity integrator usually handles this already, so the default is K_ia = 0.
