# STM32H743 Nano FC + 4-in-1 80A ESC: Electrical, Thermal and DShot/DMA Reference Model

## 0. Scope and Assumptions

No MOSFET part number, layer stack, board size or battery voltage was specified for Job #42. Every number below therefore comes from a stated, parameterized assumption. **Substitute your datasheet values before signing anything off.** The equations remain valid when you change the inputs.

**Architecture clarification:** On a 4-in-1 stack, the STM32H743 does not run the 48 kHz bridge PWM. The H743 runs ArduPilot and sends bidirectional DShot600 to four ESC MCUs (for example AT32F421 or STM32G071 running AM32/BLHeli_32). Those MCUs generate the 48 kHz complementary PWM. The model is split accordingly.

| Parameter | Symbol | Assumed value |
|---|---|---|
| Bus voltage (6S, full charge) | V_bus | 25.2 V |
| Burst phase current per motor | I_pk | 80 A (≤ 5 s) |
| PWM frequency | f_sw | 48 kHz |
| MOSFET (40 V, 5×6 PQFN class) | R_ds(on),25 | 1.0 mΩ |
| Hot R_ds multiplier at T_j = 125 °C | k_T | 1.5 → 1.5 mΩ |
| Rise + fall time at 80 A | t_r + t_f | 20 ns |
| Reverse recovery charge | Q_rr | 50 nC |
| Output charge | Q_oss | 40 nC |
| Total gate charge | Q_g | 60 nC @ 10 V |
| Dead time (each edge) | t_dt | 200 ns |
| Body diode forward drop | V_f | 0.8 V |
| Junction-to-case thermal resistance | R_θJC | 1.5 K/W |
| Board | — | 30.5 × 30.5 mm, 8 layers, 2 oz copper |

> ⚠ **Reality check:** A true *nano* (20×20 mm) 4-in-1 cannot sustain 80 A per motor even in burst. The physics below shows why. 80 A burst is credible only on a 30.5 mm board with 5×6 FETs and short bursts.

## 1. Conduction Loss Model

### 1.1 Six-step with synchronous rectification

At any commutation step:
- Phase X is the PWM leg. Its high side conducts for duty D and its low side for (1 − D).
- Phase Y is the return leg, with its low side fully on.

The current I flows continuously through one FET in each of the two active legs:

$$P_{cond} = I^2\big[R_{HS}D + R_{LS}(1-D)\big] + I^2 R_{LS} \;\xrightarrow{R_{HS}=R_{LS}=R}\; 2I^2R$$

This result is independent of duty, which is a useful property of complementary switching.

### 1.2 Temperature dependence (must be solved iteratively)

$$R(T_j) = R_{25}\,\big[1+\alpha(T_j-25)\big],\quad \alpha \approx 0.005\ \text{K}^{-1}$$

### 1.3 Numbers at 80 A

$$P_{cond} = 2 \times 80^2 \times 1.5\,\text{m}\Omega = \mathbf{19.2\ W\ per\ motor}$$

At 25 °C this would be 12.8 W. Note that the RMS phase current in trapezoidal drive is about √(2/3)·I_pk per phase *over an electrical cycle*. The bridge itself, however, always carries I through two FETs, so 2I²R is correct for the whole bridge. If you use N_p parallel FETs per switch, divide R by N_p.

## 2. Switching Loss Model at 48 kHz

| Term | Equation | Value |
|---|---|---|
| V–I overlap | ½·V·I·(t_r + t_f)·f | ½·25.2·80·20 ns·48k = **0.97 W** |
| Reverse recovery | Q_rr·V·f | 50n·25.2·48k = **0.06 W** |
| Coss | ½·Q_oss·V·f (one switch per edge pair) | **0.02 W** |
| Dead-time diode conduction | V_f·I·2t_dt·f | 0.8·80·400 ns·48k = **1.23 W** |
| Gate drive (lost in driver/R_g, not the FET) | 2·Q_g·V_gs·f | **0.06 W** |
| **Total switching-related** | | **≈ 2.3 W per motor** |

**Key insight:** At 48 kHz, dead-time diode loss exceeds hard-switching loss. Cutting t_dt from 200 ns to 100 ns saves about 0.6 W per motor. That is the cheapest thermal win on the board. Only the PWM leg switches, so this whole term belongs to one leg.

### 2.1 Total per motor and per board

$$P_{motor} = 19.2 + 2.3 \approx \mathbf{21.5\ W}$$

$$P_{board}(4\ \text{motors at } 80\,\text{A}) \approx \mathbf{86\ W}$$

Add these smaller contributions:
- Shunt or sense loss: with a 0.25 mΩ shunt, I²R = 1.6 W per motor.
- Copper trace and plane I²R: typically 2–5 W at this current.

**Realistic total: about 95–100 W.**

## 3. Thermal Model

### 3.1 Lumped heat capacity (dominant for bursts)

| Mass | Calculation | C_th |
|---|---|---|
| Copper | 8 layers × 70 µm × 930 mm² ≈ 0.52 cm³ → 4.7 g × 0.385 J/g·K | 1.8 J/K |
| FR-4 | ≈ 1.6 g × 1.1 J/g·K | 1.8 J/K |
| 16 FETs, drivers, caps | ≈ 2 g × 0.7 J/g·K | 1.4 J/K |
| **Total** | | **≈ 5 J/K** |

### 3.2 Board-to-air resistance

Assume prop-wash convection with h ≈ 60 W/m²K over about 2 × 930 mm²:

$$R_{\theta BA} \approx \frac{1}{60 \times 1.86\times10^{-3}} \approx 9\ \text{K/W}, \qquad \tau = R C \approx 45\ \text{s}$$

### 3.3 Burst transient

Since t ≪ τ, the board heating is near-adiabatic:

$$\Delta T_{board}(t) = P R_{\theta BA}\left(1-e^{-t/\tau}\right) \approx \frac{P\,t}{C_{th}}$$

With P = 95 W, the board heats at about **19 K/s**. Starting at 45 °C:

| Burst duration | Board temperature |
|---|---|
| 2 s | 83 °C |
| 4 s | 121 °C |
| 5 s | 140 °C ❌ |

### 3.4 Junction above board

Each FET dissipates about 21.5 W / 2 ≈ 10.7 W (one FET per switch).

$$\Delta T_{jc+cb} \approx 10.7 \times (1.5 + 2.5\ \text{via array}) \approx 43\ \text{K}$$

### 3.5 Verdict

For T_j ≤ 150 °C, the board must stay at or below 107 °C. That allows **about 3 s at 80 A on all four motors simultaneously**, or about 12 s on one motor.

Realistic ratings:
- Continuous: about 30–35 A per motor.
- Burst: 80 A for 2–3 s.

Mitigations:
- Use two FETs in parallel per switch. This halves conduction loss to about 9.6 W per motor.
- Reduce dead time.
- Implement firmware current limiting (AM32 current limit) plus ArduPilot `BATT_*` limits.

## 4. Bidirectional DShot600: Timing and Timer/DMA Allocation (H743)

### 4.1 Timing math

The H743 runs at 400 MHz (480 MHz on rev V). Timer kernel clock is 200 MHz on both APB1 and APB2 timers.

| Item | Value |
|---|---|
| DShot600 bit period | 1/600 kHz = 1.667 µs (333 ticks @ 200 MHz) |
| Bit "1" high time | 75% = 1.25 µs; Bit "0" high time 37.5% = 0.625 µs |
| Frame (16 bits) + reset | 26.7 µs + ≥ 2 µs |
| Bidir mode | Signal inverted (idle low → high, "1" = long low) |
| ESC turnaround | ≈ 30 µs |
| Telemetry reply | 20-bit → GCR 21-bit, NRZI, at 5/4 × 600 = 750 kbit/s, 1.333 µs/bit ≈ 28 µs |
| Full cycle | ≈ 26.7 + 30 + 28 + guard ≈ **90 µs** → max ~10 kHz loop. ArduPilot typically runs it at 1–2× the loop rate (`SERVO_DSHOT_RATE`) |
| Input capture sampling | ArduPilot uses DMA capture of edge timestamps (CCR) and decodes the GCR in software |

### 4.2 Pin and timer map (recommended)

Pair motors on as few timers as possible. Each timer needs one **UP** DMA request (burst DMAR output for all channels) plus **CHx** requests for input capture.

| Motor | Pin | Timer/Ch | Output DMA | Bidir capture DMA |
|---|---|---|---|---|
| M1 | PB0 | TIM3_CH3 | TIM3_UP | TIM3_CH3 |
| M2 | PB1 | TIM3_CH4 | TIM3_UP (shared) | TIM3_CH4 |
| M3 | PA0 | TIM5_CH1 | TIM5_UP | TIM5_CH1 |
| M4 | PA1 | TIM5_CH2 | TIM5_UP (shared) | TIM5_CH2 |
| LED (WS2812) | PA8 | TIM1_CH1 | TIM1_UP | — |
