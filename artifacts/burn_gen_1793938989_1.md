# Job #61: 3-Axis Gimbal FOC Control Loop and Dual-IMU Sensor Fusion

## 0. Assumptions and Architecture

The job spec was not provided, so the design rests on the assumptions below. Every one of them is a parameter in the code.

| Item | Assumption |
|---|---|
| MCU | STM32G4/H7-class, FPU, center-aligned PWM, ADC triggered at PWM center |
| Motors | 3× gimbal BLDC, 14 pole-pairs (12N14P-style: `N_s = 12` slots, `2p = 14` poles), high-R windings |
| Position sensor | 14-bit absolute magnetic encoder per joint (AS5048A / MT6701 class) |
| IMU A | ICM-42688-P on the **camera payload**, used for stabilization feedback |
| IMU B | ICM-42688-P on the **handle/base**, used as the vibration reference |
| Joint order | Base → Yaw (ψ, about z) → Roll (φ, about x) → Pitch (θ, about y) → Camera |

Loop rates:

| Loop | Rate | Target bandwidth |
|---|---|---|
| Current (FOC) | 20 kHz | ~1.5–2 kHz |
| Velocity (inertial rate) | 4 kHz | ~150–250 Hz |
| Angle (attitude) | 1 kHz | ~20–40 Hz |
| IMU ODR | 8 kHz | AAF ~536 Hz, decimated to 4 kHz |

Each loop's bandwidth is at least 5–10× below the loop inside it. This keeps the inner loop approximately unity gain from the outer loop's point of view, which the cascaded tuning in §2 depends on.

## 1. Field-Oriented Control (Current Loop)

### 1.1 Electrical angle

$$\theta_e = p\,(\theta_m - \theta_{m,0}) \bmod 2\pi$$

Here `p` is the number of pole pairs and `θ_m,0` is the encoder offset at d-axis alignment.

### 1.2 Clarke and Park transforms

Clarke (amplitude-invariant, with `i_a + i_b + i_c = 0`):

$$i_\alpha = i_a,\qquad i_\beta = \tfrac{1}{\sqrt3}(i_a + 2i_b)$$

Park:

$$\begin{bmatrix}i_d\\ i_q\end{bmatrix}=\begin{bmatrix}\cos\theta_e & \sin\theta_e\\ -\sin\theta_e & \cos\theta_e\end{bmatrix}\begin{bmatrix}i_\alpha\\ i_\beta\end{bmatrix}$$
