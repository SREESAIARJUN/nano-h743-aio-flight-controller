# 3-Axis Gimbal FOC Control Loop and Dual-IMU Sensor Fusion Design

I don't have the original Job #35 specification, so the design rests on the assumptions in §0. Every hardware-specific constant is a named parameter, so you can substitute your own values without changing the structure.

---

## 0. Assumptions and Timing Architecture

| Item | Assumed value |
|---|---|
| MCU | STM32G4 / H7 class, FPU, ≥170 MHz |
| Motor | Gimbal BLDC, 12N14P (p = 7 pole pairs), R ≈ 5–15 Ω, L ≈ 1–3 mH |
| Encoder | 14-bit absolute magnetic (AS5048A / MT6701), SPI |
| Current sense | 2-shunt low-side, inline amplifier |
| IMUs | 2 × ICM-42688-P on separate SPI buses, ODR 8 kHz, ±2000 dps, ±16 g |

The loops run at separated rates:

| Loop | Rate | Bandwidth target |
|---|---|---|
| PWM | 25 kHz center-aligned | — |
| Current (FOC) | 25 kHz | ω_c ≈ 2π·1500 rad/s |
| Velocity | 5 kHz | ω_v ≈ 2π·120 rad/s |
| Angle / stabilization | 1 kHz (can run at 5 kHz) | ω_θ ≈ 2π·20 rad/s |
| IMU sampling + filtering | 8 kHz → decimated to 5 kHz | — |
| Attitude estimator | 1 kHz | — |

**Design rule.** Each outer loop should have a bandwidth 5–10× lower than the loop inside it. That separation lets you tune each loop as if the inner loop were a unity-gain block.
