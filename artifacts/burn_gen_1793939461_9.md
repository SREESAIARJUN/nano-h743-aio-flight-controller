# FOC Motor Control and Dual-IMU Sensor Fusion for a 3-Axis Gimbal (Job #44)

## 0. Assumptions

I don't have the Job #44 specification, so the design rests on the parameters below. Every number lives in a `constexpr` config block or the `AxisParams` struct.

| Item | Assumed value |
|---|---|
| MCU | STM32G474 @ 170 MHz (FPU, CORDIC, 3 ADCs, HRTIM) |
| Motors | Hollow-shaft gimbal BLDC, 12N14P (pole pairs p = 7). Typical values: R = 5.5 Ω, L = 2.2 mH, Kt ≈ 0.075 N·m/A |
| Encoders | 14-bit absolute magnetic encoder (MT6701 / AS5048A) over SPI, one per joint |
| IMUs | 2× ICM-42688-P on the camera plate, SPI @ 24 MHz, gyro ±1000 dps, accel ±8 g, ODR 8 kHz. On-chip AAF set to about 1 kHz, UI filter bypassed. |
| Bus | 4S Li-ion, V_bus = 12–16.8 V |
| Loop rates | Current 20 kHz → velocity 4 kHz → angle/attitude 1 kHz. IMU fusion at 8 kHz, decimated to 4 kHz. |

**Bandwidth separation (≥5–10× per stage):**
- Current loop: ω_c ≈ 2π·1500 rad/s
- Velocity loop: ω_v ≈ 2π·150 rad/s
- Angle loop: ω_θ ≈ 2π·20 rad/s
- Drone vibration band (prop fundamental and 2nd harmonic): 80–400 Hz. This sits above ω_θ and overlaps ω_v. That overlap is why the gyro path needs notching before it closes the velocity loop.

## 1. FOC Current Loop (20 kHz)

### 1.1 Transforms
Amplitude-invariant Clarke transform, assuming i_a + i_b + i_c = 0:

$$i_\alpha = i_a,\qquad i_\beta = \tfrac{1}{\sqrt3}(i_a + 2i_b)$$

Park transform, with electrical angle θ_e = p·(θ_m − θ_off):

$$\begin{bmatrix}i_d\\ i_q\end{bmatrix}=\begin{bmatrix}\cos\theta_e & \sin\theta_e\\ -\sin\theta_e & \cos\theta_e\end{bmatrix}\begin{bmatrix}i_\alpha\\ i_\beta\end{bmatrix}$$

Inverse Park transform:

$$v_\alpha = v_d\cos\theta_e - v_q\sin\theta_e,\qquad v_\beta = v_d\sin\theta_e + v_q\cos\theta_e$$

### 1.2 Plant and PI design
The PMSM model in the dq frame is:

$$v_d = Ri_d + L\dot i_d - \omega_e L i_q,\qquad v_q = Ri_q + L\dot i_q + \omega_e(L i_d + \lambda_m)$$

**Decoupling feedforward:**
- v_d,ff = −ω_e·L·i_q
- v_q,ff = ω_e·(L·i_d + λ_m), where λ_m = Kt/(1.5p)
