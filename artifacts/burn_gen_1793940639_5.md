I don't have the Job #28 specification, so the design below uses the assumptions in §0. Every parameter is a named constant, so you can substitute the real values. Verify the ICM-42688-P register values against the TDK datasheet (DS-000347) before flashing.

## 0. Assumptions and Loop Architecture

| Item | Assumed value |
|---|---|
| Motors | 3× gimbal BLDC, 12N14P (p = 7 pole pairs), R ≈ 5–12 Ω, L ≈ 2–5 mH |
| Rotor sensors | 14-bit absolute magnetic encoder per axis (AS5048A / MT6701 class) |
| MCU | STM32G4 / H7 class with FPU, center-aligned PWM, injected ADC |
| IMUs | 2× ICM-42688-P on the camera plate, mounted diametrically about the plate centroid, SPI + DMA |
| Kinematic chain | Base → Yaw (Z) → Roll (X) → Pitch (Y) → Camera |

The control is a cascade of four rates:

```
            1 kHz                4 kHz                     20 kHz
 q_ref ─► [Attitude P + FF] ─► ω_cmd ─► [Rate PI (camera frame)] ─► τ_c
          (quaternion error)           (dual-IMU gyro)               │
                                                                     ▼
                                          τ_q = Jᵀ(θ) τ_c  (joint-space map)
                                                                     │
                                  i_q* = τ_q/K_t + i_cog(θ_m) ───────┘
                                                                     ▼
                                  [FOC current PI, d-q decoupled] → SVPWM
 IMU: ODR 8 kHz → AAF/notch on-chip → software notch + LPF → fusion (8 kHz) → decimate to 4 kHz
```

The rate loop is closed on the **inertial gyro**, not on the encoder. This is what rejects base disturbances. The encoders are used for:
- FOC commutation,
- the kinematic Jacobian,
- cogging compensation.
