# 3-Axis Gimbal: FOC Control Loop and Dual-IMU Sensor Fusion

I don't have the Job #37 specification, so I designed against a common gimbal configuration. Every assumption is a named constant in the code. Swap in your motor, inertia, and mounting data before tuning.

| Parameter | Assumed value |
|---|---|
| Motor | 12N14P gimbal BLDC, p = 7 pole pairs, R ≈ 5 Ω, L ≈ 2 mH, K_t ≈ 0.08 N·m/A |
| Commutation sensor | 14-bit magnetic encoder (AS5048A / MT6701 class) |
| MCU | Cortex-M4F/M7 with single-precision FPU (STM32G4/H7 class) |
| IMUs | 2× ICM-42688-P on the camera plate, SPI, gyro/accel ODR = 8 kHz |
| Loop rates | Current 20 kHz, velocity 4 kHz, angle 1 kHz, attitude 1 kHz |

---

## 1. Architecture

```
            1 kHz                 4 kHz                         20 kHz
θ*_cam ─►[Angle P+FF]─ω*─►[Velocity PI + AW]─i_q*─(+)─►[i_d/i_q PI + decouple]─►[SVPWM]─► Inverter
            ▲                     ▲                 ▲              ▲
            │ attitude            │ ω_axis          │ i_q,cog      │ θ_e (encoder)
     [Mahony AHRS]◄──[Dual-IMU fusion: align → AAF → adaptive notch → LPF → inverse-variance + fault vote]
                                                    │
                                    [Anti-cogging harmonic FF (LUT/LMS on θ_m)]
```

Feedback sources:

- **Angle and velocity feedback** come from the camera-plate IMUs. This is the stabilization objective: inertial pointing.
- **Commutation** uses the motor encoder.
- **Anti-cogging** is indexed by encoder mechanical angle θ_m, because cogging is fixed to the rotor and stator.
