# FOC Motor Control and Dual-IMU Sensor Fusion for a 3-Axis Gimbal (Job #47)

**Assumptions.** I don't have the Job #47 specification, so this design assumes:

- Typical gimbal BLDC motors (e.g. 12N14P, roughly 5–15 Ω) with inline current sensing.
- A 14-bit magnetic encoder per axis (AS5048A/MT6701 class).
- An STM32G4/H7-class MCU with FPU.
- Two ICM-42688-P IMUs on the camera plate, read via SPI.

Every parameter marked `// CFG` should be replaced with your measured values.

## 1. Architecture and Rate Plan

| Loop | Rate | Bandwidth target | Feedback |
|---|---|---|---|
| Current (d/q PI) | 20 kHz (PWM-synchronous) | ω_c ≈ 2π·1.5 kHz | Phase currents |
| Velocity (PI) | 5 kHz | ω_v ≈ 2π·150 Hz | Gyro rate projected onto joint axis, blended with encoder rate |
| Angle (P + I + feedforward) | 1 kHz | ω_θ ≈ 2π·25 Hz | IMU attitude (stabilization) / encoder (follow) |
| IMU sampling | 8 kHz ODR, 8 kHz processing | — | Two ICM-42688-P |
| Attitude filter | 1 kHz | — | Fused gyro + accel |

Each loop's bandwidth should be at least 5–10× below the loop inside it, so the inner loop looks like unity gain to the outer one.

## 2. FOC Current Loop

### 2.1 Transforms (amplitude-invariant)

Clarke transform:

$$i_\alpha = i_a,\qquad i_\beta = \frac{1}{\sqrt3}(i_a + 2 i_b)$$

Park transform, with electrical angle θ_e = p·θ_m − θ_offset and p the number of pole pairs:

$$\begin{bmatrix} i_d\\ i_q\end{bmatrix}=\begin{bmatrix}\cos\theta_e & \sin\theta_e\\ -\sin\theta_e & \cos\theta_e\end{bmatrix}\begin{bmatrix} i_\alpha\\ i_\beta\end{bmatrix}$$

### 2.2 Plant and PI design

The dq voltage equations of the PMSM are:

$$v_d = R i_d + L \dot i_d - \omega_e L i_q,\qquad v_q = R i_q + L\dot i_q + \omega_e L i_d + \omega_e \lambda_m$$

After decoupling, each axis is the first-order plant G(s) = 1/(Ls + R). Choose the PI zero to cancel the electrical pole:

$$K_p = L\,\omega_c,\qquad K_i = R\,\omega_c \quad\Rightarrow\quad \frac{I}{I^*}=\frac{\omega_c}{s+\omega_c}$$

The decoupling and back-EMF feedforward terms are:

$$v_d^{ff} = -\omega_e L i_q,\qquad v_q^{ff} = \omega_e L i_d + \omega_e\lambda_m$$

Discrete PI with back-calculation anti-windup (sample time T_s), where sat(·) is the circular voltage limit:

$$u_k = K_p e_k + x_k,\qquad x_{k+1} = x_k + K_i T_s e_k + K_{aw}\,(\text{sat}(u_k) - u_k), \qquad K_{aw}\approx \frac{K_i}{K_p}T_s$$

The voltage vector is limited circularly to |v| ≤ V_bus/√3, which is the linear SVPWM region. The d-axis is given priority:

$$v_q^{max}=\sqrt{V_{max}^2 - v_d^2}$$

### 2.3 Delay compensation

PWM plus computation adds about 1.5·T_s of transport delay. Advance the inverse-Park angle to compensate:

$$\theta_e^{inv} = \theta_e + 1.5\,\omega_e T_s$$

### 2.4 SVPWM (min-max injection)

$$v_{a,b,c}\ \text{from inverse Clarke},\qquad v_0 = -\tfrac12(\max + \min),\qquad d_x = \tfrac12 + \frac{v_x+v_0}{V_{bus}}$$

## 3. Cascaded Velocity and Angle Control

### 3.1 Mechanical plant (per axis)

$$J\dot\omega = K_t i_q - B\omega - \tau_{cog}(\theta) - \tau_{dist},\qquad K_t = \tfrac32 p\lambda_m$$

With the current loop treated as ideal, the plant is ω/i_q* = K_t/(Js + B).

### 3.2 Velocity PI (symmetric-optimum-style placement)

$$K_{pv} = \frac{J\,\omega_v}{K_t},\qquad K_{iv} = K_{pv}\frac{\omega_v}{N},\quad N\in[4,10]$$

The velocity feedback blends two sources. The gyro is the primary source because it measures the camera's inertial rate directly, which is what stabilization must null. It is complemented with encoder differentiation:

$$\omega_{fb} = \mathbf{a}_j^{T}\,\boldsymbol\omega_{gyro}^{fused} + \underbrace{(\omega_{enc} - \text{LPF}(\omega_{enc}))}_{\text{optional HF complement}}$$

Here a_j is the joint axis expressed in the IMU frame, obtained through the gimbal kinematic chain. The roll, pitch and yaw joints are not orthogonal to the camera frame in general, so use the inverse joint Jacobian:

$$\dot{\mathbf q} = \mathbf{J}^{-1}(\mathbf q)\,\boldsymbol\omega_{cam}$$

Velocity-loop output:

$$i_q^* = K_{pv}e_\omega + \int K_{iv}e_\omega + i_{q}^{cog} + \frac{J}{K_t}\dot\omega^{*}$$

The last term is acceleration feedforward from the trajectory generator. The integrator has back-calculation anti-windup against the I_max limit.

### 3.3 Angle loop

$$\omega^* = K_{p\theta}\,\text{wrap}(\theta^*-\theta) + K_{i\theta}\int \text{wrap}(\theta^*-\theta)\,dt + \dot\theta^*,\qquad K_{p\theta}=\omega_\theta$$

- **Stabilization mode:** θ is the IMU attitude error mapped to joint space.
- **Follow mode:** θ comes from the encoder.
