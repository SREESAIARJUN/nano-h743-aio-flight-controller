# FOC Motor Control and Dual-IMU Sensor Fusion for a 3-Axis Gimbal

I have no project files for Job #37, so this design rests on the assumptions in §0. Every number derives from a parameter you can change in one place. Measure your actual R, L, λ and J, and the code re-tunes itself.

---

## 0. Assumptions and Timing Architecture

| Item | Assumed value |
|---|---|
| Motor | Gimbal BLDC, 12N14P (N_s = 12 slots, p = 7 pole pairs). R = 5.5 Ω, L = 2.2 mH, λ = 6.0 mWb (per-phase, peak) |
| Encoder | AS5048A-class, 14-bit absolute magnetic encoder on each motor |
| MCU | STM32G4 / H7 class with FPU, 3-shunt or 2-shunt current sensing |
| IMUs | 2× ICM-42688-P on the camera plate, SPI at 24 MHz, ODR 8 kHz, ±2000 dps, ±16 g |
| Inertia (pitch) | J ≈ 1.5×10⁻⁴ kg·m² (motor plus camera about the axis) |

The loops are nested so that each runs at least 5× slower in bandwidth than the loop inside it:

```
  20 kHz ISR (PWM center-aligned)        8 kHz (IMU DRDY/FIFO)   4 kHz           1 kHz
 ┌────────────────────────────┐         ┌──────────────────┐   ┌───────────┐   ┌──────────┐
 │ ADC→Clarke→Park→PI(d,q)→   │◄─ iq* ──│ Dual-IMU fuse,    │──►│ Velocity  │◄──│ Attitude │
 │ decouple→invPark→SVPWM     │         │ AAF/LPF/notch     │   │ PI + cog  │   │ P + FF   │
 │ BW_i ≈ 1.5–2 kHz           │         │ Mahony AHRS       │   │ BW_v≈150Hz│   │ BW_θ≈25Hz│
 └────────────────────────────┘         └──────────────────┘   └───────────┘   └──────────┘
```
