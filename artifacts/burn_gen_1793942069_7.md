# 3-Axis Gimbal: FOC Control Loop, Anti-Cogging Feedforward, and Dual ICM-42688-P Sensor Fusion

I don't have the Job #11 specification, so I have stated every hardware assumption explicitly (§0). Every gain is expressed as a formula of physical parameters, so you can substitute the real values. Register values for the ICM-42688-P are given at the end. **Check them against your datasheet revision before flashing.**

## 0. Assumptions and Timing Architecture

| Item | Assumed value |
|---|---|
| Motors | 3× gimbal BLDC, 12N14P (pole pairs p = 7, slots Nₛ = 12), R ≈ 10 Ω, L ≈ 2.5 mH, Kₜ ≈ 0.07 N·m/A |
| Encoders | 14-bit absolute magnetic encoder (AS5048A / MT6701 class), SPI |
| MCU | STM32G4 / H7 class with FPU, center-aligned PWM |
| Current sensing | 2-phase inline shunts. A voltage-mode fallback is given in §1.5. |
| IMUs | 2× ICM-42688-P on the camera plate, rigidly mounted, SPI |
| Gimbal order | Yaw (outer) → Roll → Pitch (inner, camera) |

**Loop rates**

| Loop | Rate | Trigger |
|---|---|---|
| Current (FOC) | f_c = 20 kHz | PWM-synchronous ADC ISR |
| IMU sampling | ODR = 8 kHz | DMA burst read, data-ready interrupt |
| Velocity | f_v = 4 kHz | Every 5th current ISR |
| Angle and attitude | f_θ = 1 kHz | Every 4th velocity step |

**Bandwidth separation rule.** Each outer loop must be well below the loop inside it:

$$\omega_\theta \le \tfrac{1}{4}\,\omega_v,\qquad \omega_v \le \tfrac{1}{5}\,\omega_c,\qquad \omega_c \le \tfrac{2\pi f_c}{10}$$

Typical targets: ω_c = 2π·1500 rad/s, ω_v = 2π·150 rad/s, ω_θ = 2π·25 rad/s.

## 1. Field-Oriented Control (Current Loop)

### 1.1 Transforms

**Clarke** (amplitude-invariant, using i_a + i_b + i_c = 0):

$$i_\alpha = i_a,\qquad i_\beta = \tfrac{1}{\sqrt3}(i_a + 2 i_b)$$
